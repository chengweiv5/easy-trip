# Easy Trip UI 设计公式

本文档是 Android 开发实现 UI 时的设计约束与验收依据。实现应以设计文件中的具体界面为视觉基准，以本文档定义交互语义、数据关系和跨页面一致性。

## 1. 产品设计公式

```text
Easy Trip
= 地图持续提供空间上下文
+ 底部抽屉承载主要操作
+ 地点池负责收藏与安排入口
+ 行程负责按天编排
+ 本地数据始终优先
+ 网络能力渐进增强
```

核心闭环：

```text
创建旅行
→ 搜索地点
→ 连续收藏多个地点
→ 主动返回地点池
→ 从地点池多选地点
→ 选择目标旅行日
→ 追加到当天末尾
→ 编辑顺序、时间、停留时长和交通方式
→ 查看当天路线或全程路线
→ 在失败、离线和权限受限时继续完成可用操作
```

## 2. 视觉基准

### 2.1 设备与布局

- Android 逻辑尺寸基准：`390 × 844 dp`。
- 设计与实现优先遵循 Material 3 的 Android 交互习惯。
- 状态栏、系统导航栏和安全区域必须使用 `WindowInsets` 处理，不通过固定像素模拟系统区域。
- 手机界面中的内容密度、间距和控件尺寸以设计稿为准，不因列表内容增多而压缩字号或行高。
- 内容超出可视区域时使用滚动、抽屉展开或裁切提示，不缩小组件。

### 2.2 Forest Sage 视觉变量

| 语义 | 值 |
|---|---|
| 背景 `bg` | `#F5F3EE` |
| 表面 `surface` | `#FFFFFF` |
| 柔和表面 `surface-soft` | `#E7EFE2` |
| 主色 `primary` | `#2D5E3A` |
| 深主色 `primary-dark` | `#1B3A28` |
| 次要色 `secondary` | `#4A6B52` |
| 弱化文字 `muted` | `#6E7F72` |
| 边框 `border` | `#D6DDD0` |
| 强调色 `accent` | `#D96F3B` |
| 危险色 `danger` | `#BA1A1A` |
| 中圆角 | `8 dp` |
| 大圆角 | `12 dp` |

字体：

- 标题：Funnel Sans。
- 正文、数字及控件文字：Inter。
- 状态不能只靠颜色表达，必须同时使用图标、文字或形状差异。
- 阴影保持克制，优先使用表面色、边框和层级位置表达结构。

## 3. 信息架构

### 3.1 工作台

```text
工作台 = 地图层 + 顶部控制层 + 底部抽屉
```

- 地图是持续存在的空间背景，不是独立于内容的附属页面。
- 底部抽屉承载地点池和行程操作。
- 抽屉支持三档：收起、半屏、全屏。
- 抽屉内容独立纵向滚动。
- 地图缩放、定位和图层按钮浮于地图之上，不能与标题、搜索或更多菜单重叠。
- 搜索框使用不透明白色表面，保证地图背景上文字清晰。
- 图例容器宽度贴合内容，不扩展为无意义的大面积卡片。

### 3.2 一级工作区 Tab

工作台底部只有两个普通 Tab：

- 地点池
- 行程

样式：

- 透明背景；
- 选中文字使用主色和加粗；
- 选中项底部使用 `3 dp` 指示线；
- 不使用胶囊背景；
- 不出现“地点池 / 单日 / 全程”范围筛选器。

所有产品文案统一使用“行程”，不使用“每日行程”。

## 4. 地点池规则

```text
地点池 = SavedPlace 的收藏集合
行程 = ItineraryItem 的按天编排结果
```

两者必须使用不同信息结构，不能将地点池直接设计成行程列表。

- 地点池显示当前旅行的全部收藏地点。
- 地图标记区分：
  - 已加入行程；
  - 仅收藏。
- 地点池是把收藏地点加入行程的唯一入口。
- 用户可多选地点，再选择目标旅行日。
- 已经存在于目标日的地点仍允许再次加入。
- 同一个收藏地点可加入同一天多次，也可加入不同旅行日。
- 新行程项始终追加到目标日末尾，不自动排序。
- 地点池为空时显示明确空状态和搜索入口。

## 5. 搜索与收藏规则

```text
搜索结果操作 = 收藏 / 取消收藏
搜索结果操作 ≠ 直接加入行程
```

- 搜索后允许连续收藏多个地点。
- 收藏成功后停留在搜索结果页，不自动返回。
- 用户主动返回地点池后再安排地点。
- 搜索结果右侧按钮只表示收藏状态。
- 已收藏使用实心书签，未收藏使用未选中书签。
- 搜索需覆盖：
  - 初始状态；
  - 加载中；
  - 正常结果；
  - 无结果；
  - 网络失败。
- 搜索页不显示快速筛选。

## 6. 地点详情规则

```text
地点详情 = 收藏状态 + 备注 + 标签
```

地点详情不提供加入行程能力。

- 标题右侧书签负责收藏或取消收藏。
- 已收藏状态必须清晰可见。
- 页面可编辑备注和标签。
- 可说明“已收藏到地点池”，并引导通过地点池安排。
- 不显示“加入某天”“已安排到某天”等行程操作。

## 7. 行程规则

### 7.1 行程结构

行程页采用左右布局：

- 左侧：纵向天导航；
- 右侧：选中范围的行程内容。

天导航顺序：

```text
全程
第 1 天
第 2 天
…
添加
```

- “全程”位于第 1 天之前。
- “添加”固定在旅行日列表末尾，用于新增旅行日。
- 选中某一天时显示当天行程和路线。
- 选中“全程”时显示跨天连续时间轴。

### 7.2 当天行程

- 当天标题右侧使用绿色圆形“＋”添加入口，并保留“⋯”更多操作。
- 地点行必须包含：
  - 顺序或时间信息；
  - 地点名称和辅助信息；
  - `chevron_right`，进入行程项编辑；
  - `drag_handle`，用于同一天内拖动排序。
- 地点之间显示 RouteLeg。
- 拖动排序后重新生成受影响的相邻路段。
- 编辑时间、停留时长或交通方式时保留地点身份和顺序，除非用户明确拖动。
- 删除行程项必须二次确认，并突出显示将被移除的地点。
- 撤销本次加入只删除本次创建的 ItineraryItem 及受影响 RouteLeg，不删除 SavedPlace。

### 7.3 全程行程

- 使用跨天连续时间轴。
- 地图按旅行日颜色区分路线和站点。
- 只提供总览，不提供：
  - 单地点编辑；
  - 跨天拖动；
  - 旅行日换序。

### 7.4 当天无地点

- 行程内容显示空状态。
- 摘要文案格式：`第 1 天 · 暂无行程`。
- 地图不显示当天路线和编号站点。
- 其他收藏地点可以弱化标记显示，作为空间参考。

## 8. 旅行日与日期规则

```text
旅行日 = 起止日期范围连续生成的有序日期
```

- 新增旅行日只能从左侧天导航底部“添加”进入。
- 新旅行日固定追加到旅行末尾。
- 日期自动连续顺延。
- 不提供日期选择器把一天插入中间。
- 不允许单独修改某个旅行日日期。
- 不允许拖动旅行日换序。
- 旅行设置中不显示“添加一天”。
- 旅行设置中隐藏旅行日拖动手柄。

修改日期：

- 在旅行设置中整体修改起止日期。
- 根据新范围连续生成旅行日。
- 缩短日期范围前必须明确提示将删除的旅行日、行程项和路段。
- 收藏地点始终保留。

删除旅行日：

- 每行直接显示红色删除按钮，不使用更多菜单。
- 点击后进入二次确认。
- 删除当天 ItineraryItem 和 RouteLeg。
- SavedPlace 保留。
- 后续旅行日前移并重新编号。

## 9. 地图语义

### 9.1 地点池地图

- 显示全部收藏地点。
- 区分已加入行程和仅收藏。
- 不强调路线顺序。

### 9.2 当天行程地图

- 突出当天路线。
- 站点按当天顺序编号。
- 当天以外的收藏地点弱化显示。

### 9.3 全程行程地图

- 按旅行日使用不同颜色区分路线和站点。
- 保持跨天结构可辨识。
- 不把不同旅行日连接成 RouteLeg。

## 10. 本地优先与状态公式

```text
页面可用性 = 本地数据能力 + 可选网络增强
```

网络失败不能导致已保存地点、行程结构和编辑能力消失。

### 10.1 无网

- 已保存行程正常显示。
- 保留天导航、地点顺序、时间、停留时长和编辑入口。
- 仅 RouteLeg 显示“等待联网后计算”。
- 联网后自动计算。
- 地点和顺序不回滚。

### 10.2 路线失败

- 完整行程继续显示。
- 仅失败路段显示“路线计算失败 · 重试”。
- 成功路段继续显示交通方式和计算结果。
- 重试范围限定在失败路段。

### 10.3 地图加载中或失败

- 地点池和行程数据仍可查看和操作。
- 地图加载中显示明确进度状态。
- 地图失败显示失败原因语义和“重试”。
- 不使用空白地图区域代替状态反馈。

### 10.4 部分成功

场景：SavedPlace 收藏成功，但 ItineraryItem 创建失败。

- 收藏不回滚。
- 明确说明地点仍保留在地点池。
- 提供：
  - `重试加入第 1 天`；
  - `仅保留收藏`。

### 10.5 提交中与目标日失效

- 提交中禁用重复提交并显示进行中状态。
- 如果提交期间目标旅行日被删除：
  - 不静默改加到其他日期；
  - 提示目标旅行日已删除；
  - 允许用户重新选择旅行日；
  - 收藏地点保留。

### 10.6 保存失败

- 保留用户当前编辑内容，不自动回滚。
- 明确提示“修改尚未保存”。
- 提供：
  - `继续编辑`；
  - `重新保存`。

## 11. 权限规则

地图服务授权和定位权限是两套独立状态。

### 11.1 地图服务授权

- 控制地图服务是否能加载。
- 未授权时显示应用内说明和授权入口。
- 不影响本地地点池与行程数据读取。

### 11.2 定位权限

- 仅在用户点击定位按钮时请求。
- 请求前先显示应用内用途说明。
- 用户确认后再触发 Android 系统权限弹窗。
- 永久拒绝后显示前往系统设置的提示。
- 设计和 Compose 页面不复刻 Android 系统权限弹窗。

## 12. 危险操作规则

以下操作必须二次确认：

- 删除旅行；
- 删除旅行日；
- 删除行程项；
- 缩短日期范围并导致旅行日删除。

确认层必须说明：

- 被影响的实体；
- 将删除的数据；
- 将保留的数据；
- 操作是否可撤销。

危险操作使用 `danger` 色，但不能只依赖红色表达危险程度。

## 13. Compose 实现约束

### 13.1 状态与数据

- UI 从 ViewModel 暴露的 `StateFlow` 渲染。
- 本地 Room 数据作为主要事实来源。
- 网络结果写入本地后再驱动稳定 UI。
- 不以临时网络响应替代本地实体关系。
- 同一个 SavedPlace 对应多个 ItineraryItem 是合法状态，UI 不得按 placeId 自动去重。
- RouteLeg 只由同一 TripDay 内相邻 ItineraryItem 生成。
- 跨旅行日不生成 RouteLeg。

### 13.2 组件边界

建议将以下视觉模式实现为可复用 Compose 组件，但不要为了假想需求过度抽象：

- WorkspaceTabs
- WorkspaceBottomSheet
- VerticalDayNavigation
- SavedPlaceRow
- ItineraryPlaceRow
- RouteLegRow
- MapControls
- MapLegend
- EmptyState
- InlineStatus
- ConfirmationDialog
- FeedbackSnackbar

地点池行与行程地点行不得复用成一个包含大量条件分支的万能组件；它们的信息结构和操作语义不同。

### 13.3 文案与图标

- 文案统一使用“地点池”“行程”“当天行程”“全程行程”。
- 不出现“每日行程”。
- `bookmark` 表示收藏状态。
- `chevron_right` 表示进入编辑。
- `drag_handle` 表示同一天内排序。
- 圆形 `add` 表示向当天追加地点。
- 图标必须有可访问性描述；纯装饰图标可明确标记为无语义。

### 13.4 可访问性

- 触控目标遵循 Android 最小尺寸要求。
- 文本和背景保持足够对比度。
- 状态信息不能只靠颜色。
- 收藏、选中、失败和禁用状态应可被辅助技术识别。
- 动态状态变化通过合适的语义或反馈组件告知用户。

## 14. 开发验收清单

### 视觉

- [ ] 使用 Forest Sage 色彩和字体体系。
- [ ] 工作台地图持续可见，抽屉承载操作。
- [ ] 地点池与行程使用不同列表结构。
- [ ] Tab 是透明背景、选中文字和 3 dp 指示线，不是胶囊。
- [ ] 搜索框是不透明白色。
- [ ] 图例容器贴合内容。
- [ ] 内容增多时没有压缩字体、地点行或 RouteLeg。
- [ ] 收起、半屏、全屏三档抽屉视觉和交互一致。

### 交互

- [ ] 搜索结果只收藏，不直接加入行程。
- [ ] 搜索后可连续收藏并由用户主动返回。
- [ ] 地点详情只管理收藏、备注和标签。
- [ ] 加入行程只从地点池发起。
- [ ] 新行程项追加到目标日末尾。
- [ ] 同一地点可被重复加入。
- [ ] 新增旅行日只从天导航“添加”发起。
- [ ] 旅行日连续生成且不可拖动换序。
- [ ] 全程页面不提供单地点编辑或跨天拖动。

### 状态

- [ ] 无网时完整行程仍显示和可编辑。
- [ ] 路线失败只影响对应 RouteLeg。
- [ ] 地图失败不阻断地点池和行程操作。
- [ ] 部分成功时收藏不回滚。
- [ ] 保存失败时编辑内容不回滚。
- [ ] 目标旅行日失效时不静默改投其他日期。
- [ ] 定位权限只在点击定位后请求。
- [ ] 永久拒绝定位后提供前往系统设置入口。

### 验证

- [ ] Compose Preview 只用于局部检查，不能替代运行验证。
- [ ] 在 Android 模拟器或真机实际走通核心闭环。
- [ ] 检查小屏、长列表、长地点名和长日期列表。
- [ ] 检查系统返回、手势返回、旋转或进程恢复涉及的状态。
- [ ] 运行项目测试、类型/编译检查和 lint。

## 15. 冲突处理优先级

发现实现、旧文档和设计稿冲突时，按以下顺序判断：

1. 当前已确认的产品规则与本文档；
2. `easy-trip-v1.0.pen` 中对应流程和状态界面；
3. 最新产品规格文档；
4. 旧设计稿、旧 TODO 和现有代码行为。

不得为了迁就旧代码而改变已确认的产品语义。若设计稿中的具体视觉与本文档的交互规则冲突，应先记录冲突并请求产品决策，不自行创造折中行为。
