# Easy Trip 设计实现指南

本文档指导 Claude Code 根据 `design/easy-trip-v2.0.pen` 分批实现 Easy Trip Android Jetpack Compose 应用。设计文件负责表达视觉、状态和交互，现有 Android 工程负责提供业务模型、数据约束和运行架构。

## 1. 事实来源与优先级

开发时按以下顺序判断：

1. 当前用户明确确认的需求。
2. `design/easy-trip-v2.0.pen` 中对应顶层界面的可见内容与 `context`。
3. `f7rS8 · Easy Trip UI Kit` 和 `DxZ2a · 14 状态规范`。
4. 本文档。
5. `design/EASY_TRIP_IMPLEMENTATION_PLAN.md` 中记录的已确认映射。
6. 当前代码中的数据模型、数据库约束和可复用架构。
7. 旧设计、旧文档和旧实现行为。

发现冲突时不得静默折中。先记录冲突、影响和推荐处理方式；只有不同选择会导致实质性产品差异时才请求用户决策。

`design/easy-trip-design-formula.md` 是较早版本的规则记录，其中“地点池是加入行程的唯一入口”等内容已经被当前双入口设计替代。当前实现以本指南和 `easy-trip-v2.0.pen` 为准。

## 2. Claude Code 开始工作前必须执行

1. 阅读仓库根目录 `CLAUDE.md`、本文档和 `design/EASY_TRIP_IMPLEMENTATION_PLAN.md`。
2. 执行 `git status --short`，识别现有未提交改动。
3. 不重置、不覆盖、不清理与当前批次无关的改动。
4. 若 `graphify-out/graph.json` 存在，先执行：

   ```bash
   graphify query "本批涉及的页面、状态、导航、组件和测试在哪里实现？"
   ```

5. 通过 Pencil MCP 读取本批设计，不直接全量解析 `.pen` 文件。
6. 先建立本批 frame 到 Composable、UiState、导航、数据操作和测试的映射，再进入实现。
7. 非简单修改先进入计划模式，用户批准后再写代码。
8. 未经明确要求，不 commit、不 push。

如果本机没有 `graphify` 命令或没有可用的 Pencil MCP，必须明确说明哪些检查无法执行，不能假装已经读取设计或更新知识图。

## 3. 如何读取 `.pen` 设计

每个开发批次只读取必要范围：

1. `f7rS8 · Easy Trip UI Kit`。
2. `DxZ2a · 14 状态规范`。
3. 本批主流程涉及的顶层手机 frame。
4. 对应附录状态和必要的局部节点。
5. 用于视觉核对的局部截图。

读取规则：

- 顶层 frame 的可见内容定义布局、样式、内容密度和浮层关系。
- 顶层 frame 的 `context` 定义入口、交互、状态含义和跳转关系。
- 顶层名称中的数字编号用于需求引用，不等于一条独立导航路由。
- 名称以“附录引用”开头的 frame 是状态验收材料，不重复实现为页面。
- “旅程 A/B/C…”和“状态组 A/B/C…”是流程编排画板，不实现为应用页面。
- 同一页面的多个设计状态应由同一个 Composable 和参数化 UiState 表达。
- 设计中的静态滚动条只表达滚动能力；代码中使用真实滚动容器，不绘制假滚动条。
- 设计中系统状态栏、系统导航栏和权限弹窗不按像素复刻，使用 Android `WindowInsets` 和系统权限 API。

修改设计文件时才需要遵循 pen-dev skill、`.pen` schema、placeholder 和 execute API 规则。只读取设计并实现 Android 代码时，不需要把完整 `pen-schema.md` 或 `execute.md` 复制进项目上下文。

## 4. 设计覆盖与实现归并

当前设计包含 92 个手机画面：

- 59 个主界面或主流程状态。
- 33 个附录引用。
- 44 个数字编号加 `07A`，共 45 类界面。

这些画面不能一比一生成 92 个 Composable。应归并为：

```text
页面外壳 + UiState + 弹层状态 + 一次性反馈
```

示例：

- “我的旅行”“单个旅行”“多个旅行”“删除后”“空状态”由旅行列表页面及其状态模型覆盖。
- “搜索地点”“加载中”“无结果”“网络失败”由搜索页面及异步状态覆盖。
- “选择日期”“长日期列表”“无旅行日”“旅行日已删除”由加入行程流程的状态覆盖。
- 抽屉收起、半屏、展开是同一工作台抽屉的状态，不是三个页面。
- 地图加载中、加载失败和正常地图是同一工作台地图区域的状态。

禁止为了还原截图创建平行的数据源、重复 ViewModel 或只在测试中可达的伪页面。

## 5. 视觉令牌

逻辑尺寸基准：`390 × 844 dp`。实际 Android 实现必须适配 WindowInsets、不同屏幕尺寸、字体缩放和系统导航模式。

| 语义 | 值 |
|---|---|
| `bg` | `#F5F3EE` |
| `surface` | `#FFFFFF` |
| `surface-soft` | `#E7EFE2` |
| `primary` | `#2D5E3A` |
| `primary-dark` | `#1B3A28` |
| `secondary` | `#4A6B52` |
| `muted` | `#6E7F72` |
| `border` | `#D6DDD0` |
| `accent` | `#D96F3B` |
| `danger` | `#BA1A1A` |
| 中圆角 | `8 dp` |
| 大圆角 | `12 dp` |
| 标题字体 | Funnel Sans |
| 正文字体 | Inter |

约束：

- 状态不能只靠颜色表达，必须结合图标、文字或形状。
- 阴影保持克制，优先用表面色、边框和位置层级表达结构。
- 不因列表变长而压缩字号、行高或触控区域。
- 若 Android 字体资源暂未包含设计字体，先报告差异，再采用项目已有字体策略；不要静默引入不明来源字体文件。

## 7. 工作台与抽屉规范

工作台结构：

```text
地图层 + 顶部控制层 + 底部主抽屉 + 临时操作/模态层
```

主工作区抽屉三态：

| 状态 | 设计位置 | 高度 |
|---|---:|---:|
| 收起 | `y=674` | `108` |
| 半屏 | `y=350` | `432` |
| 展开 | `y=62` | `720` |

临时浮层：

| 类型 | 设计位置 | 高度 |
|---|---:|---:|
| 临时操作抽屉 | `y=294` | `550` |
| 短表单抽屉 | `y=454` | `328` |

实现要求：

- 标题和底部主要操作固定，长内容只滚动中间内容区。
- 主抽屉可在收起、半屏、展开之间拖动。
- 遮罩、Dialog、菜单和临时操作抽屉必须位于地图按钮之上。
- 地图控制按钮不得穿透或覆盖模态内容。
- 权限说明和地图图层选择可使用内容型浮层。
- 删除确认保持居中模态语义。
- 当前画布中的部分历史操作抽屉可能仍保留旧高度；实现以本节和 `DxZ2a` 为准，同时在对应批次核对具体 frame，记录可见差异。

## 8. 地图地点状态

- 已安排：绿色实心圆，内部白色 `bookmark`。
- 仅收藏：白色圆、绿色描边，内部绿色 `bookmark`。
- 已安排地点不显示数字；路线页需要表达行程顺序时，顺序属于路线站点语义，不改变收藏/已安排图例定义。
- 地点池地图首次进入时自动缩放到展示全部收藏地点。
- 用户手动缩放或移动后，才允许部分地点移出视野。
- 单日路线进入时自动缩放并保留安全边距，避开标题、搜索栏、右侧地图控件和底部抽屉。
- 全程路线展示所有旅行日地点，并按各自交通路段连接；不同旅行日之间不生成 RouteLeg。

## 9. 地点池与行程双入口

### 9.1 单地点入口

```text
地点池单个地点右侧加号
→ 09 加入行程 · 选择日期
→ 选择一个或多个旅行日
→ 成功、部分成功或失败反馈
```

单个收藏地点可以加入多个旅行日。

### 9.2 旅行日入口

```text
行程页选中某一天
→ 点击当天“添加地点”
→ 19 从地点池添加地点
→ 批量选择多个收藏地点
→ 加入当前旅行日
```

两个入口共享底层用例和数据约束，但入口上下文、选择对象和 UI 状态不同，不能合并成完全相同的界面状态机。

### 9.3 数据约束

- 同一个 SavedPlace 对应多个 ItineraryItem 是合法状态。
- 同一地点可加入同一天多次，也可加入不同旅行日。
- UI 不得按 `placeId` 自动去重行程项。
- 新行程项追加到目标日末尾。
- RouteLeg 只由同一 TripDay 内相邻 ItineraryItem 生成。
- 撤销加入只删除本次创建的 ItineraryItem 及受影响 RouteLeg，不删除 SavedPlace。

## 10. 行程与路线

- 左侧范围导航顺序为“全程、第 1 天、第 2 天……、添加”。
- 选中某一天时显示当天地点、顺序和交通路段。
- 地点右侧 `chevron_right` 进入行程项编辑。
- 地点间交通路线进入交通路段编辑。
- `drag_handle` 只用于同一天内排序。
- 删除行程项必须确认，只删除本次安排并保留地点收藏。
- 选中“全程”时，地图展示全部旅行日地点，抽屉按日期连续分组展示完整行程。
- 全程视图不提供跨天拖动或单地点编辑。

## 11. 通用状态规范

所有状态必须：

1. 保留已有用户数据。
2. 说明发生了什么。
3. 给出明确下一步。
4. 用图标、文字和颜色共同表达。

状态组：

- 内容为空。
- 等待联网。
- 加载或计算中。
- 失败可恢复。
- 权限说明。
- 成功反馈。

关键约束：

- 网络失败不隐藏已保存地点和行程。
- RouteLeg 失败只影响对应路段。
- 地图失败不阻断地点池和行程操作。
- 部分成功时收藏不回滚。
- 保存失败时保留用户输入。
- 目标旅行日被删除时不静默改投其他日期。
- 成功反馈可提供“撤销”和“查看结果”。

## 12. 权限与危险操作

地图服务授权和定位权限是两套独立状态：

- 地图服务未授权不影响本地地点池和行程读取。
- 定位权限只在用户点击定位按钮后请求。
- 系统权限弹窗由 Android 系统提供，设计只实现请求前说明和永久拒绝后的设置引导。

以下操作必须二次确认：

- 删除旅行。
- 删除旅行日。
- 删除行程项。
- 缩短日期范围并导致旅行日删除。

确认界面必须说明被影响实体、删除内容、保留内容和可撤销性。

## 13. 分批实现顺序

### Batch 0：设计映射和基础设施

- 建立 frame 到代码的映射。
- 收敛 Theme、token 和基础组件。
- 收敛地图工作台外壳、抽屉状态和浮层层级。
- 收敛地图标记、空状态、Dialog 和反馈组件。

### Batch 1：我的旅行和创建旅行

- 我的旅行：空、单个、多个、滚动和删除后状态。
- 创建旅行初始、日期、校验和成功进入工作台。
- 旅行设置、修改日期、删除旅行。

### Batch 2：旅行工作台骨架

- 地点池/行程切换。
- 全空和行程全空。
- 地图、顶部栏、主抽屉三态。
- 图层浮层和地图控制层级。

### Batch 3：地点池、搜索和地点详情

- 地点池短列表、长列表和空状态。
- 搜索加载、结果、无结果和失败。
- 连续收藏/取消收藏。
- 已安排/仅收藏标记。
- 已安排和仅收藏地点详情。

### Batch 4：加入行程双入口

- 单地点选择多个旅行日。
- 从旅行日批量选择多个地点。
- 长日期列表、无旅行日、部分成功、旅行日失效和撤销。

### Batch 5：行程编辑和路线

- 行程项编辑与删除确认。
- 交通路段编辑。
- 单日路线和全程路线。
- 日期分组、自动缩放和安全边距。

### Batch 6：异常、权限和最终收敛

- 离线、加载、失败、权限和恢复状态。
- 可访问性、长文案、字体缩放和进程恢复。
- 最终视觉和实体设备验收。

## 14. 每批固定工作流程

1. 检查 `git status` 和目标文件 diff。
2. 查询 Graphify；命令不可用时记录原因。
3. 用 Pencil MCP 读取本批 frame、context、UI Kit、状态规范和必要截图。
4. 更新本批设计到代码映射。
5. 先给出具体文件、状态、导航、数据和测试计划。
6. 实现可操作的端到端闭环，不只实现静态布局。
7. 增加或更新必要的单元测试和 Compose UI 测试。
8. 在模拟器或实体设备实际操作关键路径。
9. 运行适用检查：

   ```bash
   ./gradlew assembleDebug
   ./gradlew testDebugUnitTest
   ./gradlew lintDebug
   ./gradlew connectedDebugAndroidTest
   ```

10. 代码修改后运行 `graphify update .`。
11. 更新 `design/EASY_TRIP_IMPLEMENTATION_PLAN.md`。
12. 最终报告通过、失败和未运行的检查，不隐瞒失败。

## 15. 批次验收门槛

阻塞批次的问题：

- 功能或状态错误。
- 数据不一致。
- 崩溃。
- 流程不可达。
- 严重裁切。
- 关键交互失效。

不阻塞批次、留到最终实体设备验收的问题：

- 小范围间距差异。
- 轻微字号或字体渲染差异。
- 非关键的视觉基线差异。
- 不影响理解和操作的地图素材裁切。

不要求每个画面逐像素截图比对。代表性截图可以保留为诊断证据。
