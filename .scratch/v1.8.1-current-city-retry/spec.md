# v1.8.1：搜索失败后主动重试当前城市

## 用户要求

- 搜索报错“无法获取当前城市”。
- 用户确认：每次主动点击搜索都应该重新尝试，不能继续返回旧的定位失败。

## 范围

- 定位或城市解析失败后，点击顶部搜索按钮、键盘搜索键或“重试定位”，重新尝试失败请求。
- 仍在执行的定位请求继续共享，成功且未过期的坐标与城市继续复用。
- 输入时的防抖自动搜索不反复启动定位；没有城市时不退化成全国搜索。
- 不改变成功搜索后的地图交互、视觉设计、定位权限、SDK 网络协议和后台定位策略。
- 首轮交付为本地修复。2026-10-08 用户追加“提交推送，安装”：将版本递增为 `1.8.1 / 11`，在功能分支提交，快进推送到 `origin/main`，用相同正式签名覆盖安装到已连接手机，保留业务数据。不创建 GitHub Release 或发布标签。

## 已核验的故障边界

2026-10-08 在连接的手机读取到正式版 `1.8.0 / 10`，精确与粗略定位权限均已授予。搜索页显示“定位失败（4）”，点击原有“重试定位”后仍失败。当前依赖 SDK 定义错误 4 为 `ERROR_CODE_FAILURE_CONNECTION`。

在未修改网络或权限的情况下，独立 SDK 诊断稍后成功，应用重新进入后搜索也恢复。因此能确认真实定位连接失败曾发生，不能确认该次连接失败的网络底层原因，也不能将稍后恢复归功于本次尚未安装的修复。

代码缺陷是：自动搜索/启动定位的失败被 `AppLocationSession` 缓存，`Submit` 只重跑 POI 搜索链路，不像原来的专用重试入口那样清除失败请求，导致用户点击搜索仍重复得到旧错误。

## 验收

- 首次定位失败后，连续主动搜索会发起新的定位尝试。
- 坐标成功、城市解析失败时，只重试城市解析。
- 已成功定位不增加定位或城市解析请求。
- 连续点击不取消或重复创建正在执行的共享定位请求。
- 三个真实界面入口都能从定位失败恢复到带真实城市的搜索结果。
