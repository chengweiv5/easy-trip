## 用户确认的方案

用户提出同一地点可能同时吃饭和住宿，并确认按以下方案继续设计：

1. **一个行程地点可以有多笔费用**，每笔独立金额、类别和备注。
2. 每笔单选六类之一：**住宿、交通、景点、吃饭、购物、其它**；同一类别也可以记多笔。
3. 地点展示费用合计，进入费用列表后逐笔添加、编辑或删除。
4. 费用归属于某天的某次行程安排，而不是全局地点；同地点在多天出现不重复计费。
5. 统计按费用记录汇总，不把一个金额同时归多个类别，不按地点ID去重丢弃其它费用。

原首稿“每个行程项只有一个金额”的限制已被替代。首稿审计原文保存在 `history/first-draft/`，仅供历史追溯，不作为当前规格。

## 本轮交互细化

以下已表达在设计中，作为本轮待评审的具体交互，不把方案确认等同于代码实现授权：

- **地点编辑与费用编辑分离**：地点编辑页显示只读合计、笔数和管理入口；时间／停留／地点备注草稿保留。费用逐笔独立保存，取消地点编辑不回滚已保存的费用。
- **单笔新增／编辑**：类别和金额必填，备注选填；0元合法、空金额不是0。首屏不提前报错；负数、超过两位小数、金额或合计溢出时拒绝保存。金额、类别和备注原子保存；失败留稿、不覆盖其它笔；保存中防重复操作。
- **取消与删除**：有改动的草稿退出前确认；删除只针对当前费用，确认显示金额与影响，失败不扣减；删除成功刷新各级汇总。删除最后一笔回到未记录状态。
- **明细与统计**：全程／单日／分类范围保留；同地点同类别多笔分别显示。改类别只移动分类小计；成功返回原范围及位置。
- **日期归属**：再次安排同地点创建空费用集合，不复制旧费用。移动原行程项时全部费用随行，保持原费用ID与全程合计，只改变日小计。跨日房费整笔归记录所在日，不自动摊销；需要按天记账时可分别录入。
- **旧费用兼容**：每个旧地点非空金额迁为一笔原额待分类记录，不猜类别、不自动拆分；旧0元保留、空值不生成费用。旧交通归交通，稳定映射防重复迁移。已记总额 = 六类已分金额 + 待分类金额。
- **交通路段边界**：本轮用户确认的是地点多笔，路段仍沿用既有单金额编辑并固定归交通，没有顺带扩展路段多笔。
- **边界状态契约**：加载／失败不显示假合计；来源行程失效时禁止保存，不转挂其它地点；键盘／大字体时正文可滚动、动作可达。删除地点／旅行日／重建路线须统计全部受影响费用并确认。
- 不增加预算、AA、跨地点独立旅行账本、多币种或费用导出。
