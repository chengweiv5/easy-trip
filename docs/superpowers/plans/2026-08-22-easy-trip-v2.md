# Easy Trip v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保持 v1 本地优先架构与数据兼容的前提下，升级旅行工作台的视觉状态、搜索地图联动、地图图层与视野控制、行程时间轴和应用图标。

**Architecture:** 继续使用单 `app` module 和现有 Room/Repository/ViewModel 分层。`TripWorkspaceViewModel` 统一管理工作台导航、搜索焦点与地图命令，`MapPreferences` 持久化全局图层，`AmapMapHost` 增量应用图层和一次性相机命令；搜索、地点池、每日行程拆为三个独立内容 Tab。v2 不修改 Room schema。

**Tech Stack:** Kotlin、Jetpack Compose、Material 3、Navigation Compose、ViewModel、SavedStateHandle、StateFlow、Room、高德 Android Map SDK、JUnit、Compose UI Test。

**Spec:** `docs/superpowers/specs/2026-08-22-easy-trip-v2-design.md`

## Global Constraints

- 继续使用单体 Android `app` module，不新增依赖注入框架。
- 不修改 Room schema；现有 v1 数据必须可直接打开。
- 未授权或离线时，地点池和每日行程仍可查看与编辑。
- 地图、搜索和路线功能必须遵守现有高德 consent token 生命周期。
- 相同地图模型、Tab 切换、抽屉变化和普通重组不得重建 `MapView` 或重置视野。
- 未选控件必须透明、无描边；选中控件使用主题色实心背景和反白文字。
- 搜索结果点击后聚焦并高亮 marker，但详情仍留在搜索 Tab。
- 地图图层选择为应用级本地偏好，跨旅行和重启保留。
- 不把 API Key、keystore、密码或设备序列号写入 tracked 文件。
- 不 commit、不 push；每个任务完成后只记录验证结果和待审查状态。
