# v3.2.0 Release Implementation Plan

**Goal:** 将已验证的助手交互、城市规则、节流及抽屉相机修复提交到主线，并发布 v3.2.0 正式 APK。

**Architecture:** 不新增产品功能。功能分支提交 → 干净提交构建验证 → 主线快进推送并读回 → 固定标签与草稿资产 → 下载验证后公开 → 文档收尾提交。

**Tech Stack:** Kotlin / Compose、Gradle、Android SDK36、Git、GitHub Releases。

**Spec:** 用户授权“提交，推送，发布 v3.2”；功能及验收边界见 `docs/testing/assistant-drawer-camera.md`、`docs/testing/assistant-next-round.md`、`docs/testing/unified-search-city.md`。

## Global Constraints

- 3.2.0 / build25 / schema11，沿用正式签名；不卸载、清数据、降级或再安装真实手机。
- 使用现有功能分支；只向 `origin/main` 快进推送，推前 fetch，必要时 rebase，不强推。
- 新标签不得移动或覆盖；APK 与 SHA256 文件验证后才公开，并确认 Latest。
- 保留唯一 v3.2 累积 Pencil 源，不更改冻结 v3.1；本轮仅发布，设计字节保持已验证状态。
- 原有失败和真实模型／系统相册／TalkBack／极小窗口边界不隐去。

## Review Focus

- 未提交安装包必须与本轮 CLEAN 正式构建区分，以 APK 内 GIT_SHA / SOURCE_STATE 验证。
- 防止远端并发更新丢失：提交、推送、标签和公开前核验远端。
- 同名 build25 体验包可能不提示更新；发布说明须明确手动覆盖，不自动升级手机。
- 助手抽屉不能改变视角，但新结果／主动候选定位和行程自身恢复适配必须保留。
- 草稿创建或下载延迟不应触发重复 Release；按 tag 唯一定位草稿，回读资产内容与哈希。

## Task 1: Commit and validate

- [ ] 备份当前源码、设计及文档；确认待合并 PR 和 v3.2 标签不存在。
- [ ] 提交已验证修复与既有安装文档；检查提交范围无配置、密钥或 APK。
- [ ] 从干净提交构建 Debug／Release／AndroidTest，运行全量 JVM 与 lint。
- [ ] 自有软件渲染模拟器执行助手、城市、Room／迁移及抽屉相机专项，复测 320dp／2倍字体。

## Task 2: Deliver main and release assets

- [ ] fetch／必要时 rebase，快进推送 main，独立回读 SHA。
- [ ] 核验 APK 签名、版本、16KB 对齐、CLEAN 和构建 SHA，归档 APK 与校验文件。
- [ ] 创建固定 v3.2.0 标签及唯一草稿，上传两项资产，认证完整下载校验。
- [ ] 公开为非预发布 Latest；匿名完整下载及 Latest／tag 回读校验。

## Task 3: Close out

- [ ] 更新 `README.md`、`docs/testing/v3.2.0-release.md`、`AGENTS.md`，准确记录来源、验证与限制。
- [ ] 清理自有模拟器并释放锁，保留证据和回滚备份。
- [ ] punk-12 通知并独立回读，再写回 `.codex/TASK_STATE.md`。
- [ ] 文档提交快进推送并回读远端；发布标签仍指向 APK 构建提交。
