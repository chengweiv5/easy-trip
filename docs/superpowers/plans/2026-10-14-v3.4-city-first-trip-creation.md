# v3.4 城市优先创建旅行 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> 用户已选择本会话串行实施；本轮不启动子代理。执行记录见文末与实施报告。若上述技能在执行环境不可用，明确说明并遵守已获批准的执行方式及本仓库门禁，不假称已经调用。

**Goal:** 全局助手仅识别目的地，确认创建后自动把原攻略和城市范围交给新旅行的既有助手，最终由用户手动收藏。

**Architecture:** 新增独立城市准备状态机，不再让全局入口绑定 `AssistantTarget.NewTripDraft` 的地点控制器。通过一个 Room 事务创建空旅行、日期、城市上下文、一次性交接和防复活回执；workspace 复用标准打开助手动作领取交接并调用原地点管线。新旧创建命令、回执和日志分别解码，保留旧流程恢复能力。

**Tech Stack:** Kotlin、Jetpack Compose、ViewModel／StateFlow、coroutines、Room、kotlinx.serialization、既有 OkHttp 模型传输和高德数据源；不新增依赖。

**Spec:** [2026-10-14 城市优先规格](../specs/2026-10-14-v3.4-city-first-trip-creation-design.md)，用户于2026-10-14确认；[C00–C37 UI](../../../design/v3.4.0-city-first-review.md)同时确认。

## Global Constraints

- 全局不调用地点 parser／normalizer，不查询高德；不先构造候选再反推城市。
- 一次“创建并导入攻略”确认；日期可选，仅解析用户计划，不采用分享标题、作者日期或shareTime。
- 最终100地点、编号至CV、20图片、每批1条链接、1–30天空白行程日；超限完整拒绝，不截断或部分收藏。
- 700ms发起间隔／并发2、180秒普通文字批次、8192输出预算和不小于1MiB有界恢复日志保持。
- 单城作为批次默认城市；多城完整传递、逐项按证据归属，不以第一城、定位或旅行名称覆盖不确定项。
- 自动领取一次不等于远端网络exactly-once；已领取且请求结果未知时人工重试，明确可能重复计费。
- 创建、上下文、交接和回执在一个事务内；导入失败／取消／零地点保留旅行；删除后不复活。
- 保持作者证据、泛称／别名语义去重、底图背景过滤、餐饮剔除、独立子地点保护及手动收藏。
- UI必须符合已确认C系列；不恢复名称说明或日期成功提示卡，不更改首页左右双入口。
- 只前向迁移：设计采用schema12→13新增表；保留旧schema12回执及100地点日志。具体schema文件由Room生成，禁止手填identity hash。
- 执行前再核对main／开放PR与本树变更，保留当前设计；在功能分支实施，不清空用户数据、不安装真实手机。
- 后续用户“好”已批准本会话串行实施；未授权Git提交推送、安装真实手机或发布。以下为原计划；完成标记以实际证据为准，不把示意接口和命令视为逐字执行结果。

## Review Focus

1. **城市正文与用户计划混在同一分享文本。** 城市可从攻略提取，但日期来源只能是明确用户自述；Task 1／2钉住分享标题“三日游”和作者日期污染。
2. **两个界面或两个恢复协程同时消费同一交接。** 只一个领取成功，准备条件未满足时不领取；Task 4／7钉住CAS、旋转与设置返回。
3. **全局页退出触发图片清理，而旅行内尚未处理。** 已提交交接持有素材引用；Task 2／4钉住文件所有权、数据库失败和取消清理。
4. **旅行改名或手机位于另一城市。** 持久目的地范围仍有效，人工城市优先；Task 5钉住多城、无城市和重命名。
5. **升级时存在旧“创建并收藏”未决记录。** 只执行旧命令恢复，不把100个旧候选降格为空旅行或自动重复导入；Task 4／6／8钉住升级与删除防复活。
