# v3.3 携程／小红书粘贴链接规格

日期：2026-10-13。用户已要求完成规格后直接开发，不再逐阶段等待确认；首批两平台、已有旅行、图片上限暂定 20 张。不新增页面或改变助手布局，只同步必要文案／状态到 Pencil。

## 1. 用户行为

用户在已有旅行助手粘贴纯 URL 或完整分享文案，仍点击“全部标记到地图”。粘贴不联网。每批一条唯一链接；相同 URL 重复出现只算一条。仅支持携程社区笔记和小红书笔记／分享短链，不接店铺、订单、酒店、视频或大众点评。没有 URL 时保持既有纯文字／选图路径。

点击发送后先验证输入，再读取正文／原帖轮播图片，取得全部素材后才进入现有模型、POI 查询、候选选择和收藏。保留用户附加说明；网页自身内容仅作为不可信素材，不授予工具或写入权限。失败不得将分享标题冒充正文发送。

## 2. 获取层

使用本机 WebView（逐任务实例、应用级串行门控，共享系统一方 CookieManager，不是独立浏览器进程），默认 UA、正常 HTTPS 页面。携程先正常访问首页，再打开原始分享 URL。小红书保留短链全部参数，正常跳转后只读笔记 DOM。静态提取脚本只读 DOM，无 JS bridge、隐藏接口、账号 Cookie 导入或验证码代解。拦截外部 scheme、文件访问、新窗口、权限请求和非平台导航；平台/CDN 域名白名单与无凭据 HTTPS URL 校验限制浏览范围；图片下载器另行检查 DNS，拒绝内网与回环地址。WebView 的 DNS／子资源重定向由平台网络栈处理，不声称具备逐跳 DNS 固定。

每次最多等待 45 秒得到完整页面；根据正文、原帖图片列表和张数稳定性判断，不将固定等待当作成功。登录／验证、页面不支持、删除、缺失正文、图片不齐明确失败。无计数器仅在正文、单图和页面加载完成均可确认时接收；无配图或结构未知的笔记保守拒绝，不把未知张数当零。下载图片沿用页面实际 URL；小红书已观察到的 HTTP CDN 图升级 HTTPS，不降低混合内容或 TLS 安全要求。原帖图片按轮播顺序去重，排除头像、评论、相关推荐。

## 3. 20 图与资源边界

所有入口统一最多 20 张（链接图与已选图片合计）。单图 10 MiB、整批 30 MiB、处理后单图 4 MiB、既有像素保护保留；这些是独立限制，UI 不承诺任意大小的 20 张都能接收。平台原帖超过剩余名额时整次链接读取失败，不截断、不将前二十张报告为全部。

按张下载、校验并暂存，逐张解码和模型请求，不同时在内存中持有 20 张位图或一次性向模型提交 20 图。链接抓取失败／取消删除本次新增文件，保留原有附件；全部下载成功才将新图合入草稿。每张来源和序号稳定，可预览、重试。整批模型处理预算按素材数计算，上限 30 分钟；单请求 45 秒保护保持，用户随时可取消。

图片数不改变每批最多 30 个最终地点的业务约束。链接素材单份最多提取 100 个候选、合并最多 400 个候选，这是内部安全预算，不是收藏上限。相同字面名称先合并来源；全部素材理解成功后，统一调用一次模型，在地图查询前做语义去重和过滤：

- System Prompt 是按处理阶段固定的通用规则模板，不随旅行生成或写入具体城市、景点、食品示例；每次请求只在 User 消息中传入本次城市、正文和候选证据。规则只随代码版本变化。
- 同一实体的简称、全称、别名或带有／省略通用类别后缀的名称，仅在本次资料和来源证据能确认相同时合并，不靠名称相似或删后缀推断。缺少专名的泛称只有上下文唯一指向某个已有明确候选时才合并，不补造名称。不同城市、同名分店或独立的包含关系不强行合并。
- 按最新用户决定，单独食品／菜品和所有餐饮地点都剔除，包括饭店、餐厅、小吃、早餐、糕点、饮品店，即使有明确店名也不保留。住宿酒店、客栈及其他非餐饮地点仍保留，不能仅按“店／饭店”字样判断。
- 地图背景标注不等于推荐目标；只保留有依据的目的地。模型只能对已有候选 ID 分组或解释丢弃，不能添加新名字、城市或坐标；本地校验完整覆盖、重复 ID、跨城合并及额外字段。
- 地图图片在提取阶段先区分作者叠加内容和底图：以作者编号停靠点、图片气泡、箭头／圈注对应目标及明确推荐为依据。路线经过、贴近或圈内普通地名不等于停靠；底图绿色景区名／图标也不是作者推荐。背景项直接省略，不以`uncertain=true`混入。不能只按颜色、字号、类别或“村”字判断，真正推荐的古村保留；无编号图仍可依据明确推荐标签／介绍／清单提取。
- 最终仍超过 30 时完整拦截，不为凑数丢弃合法地点、不截断、不发起地图查询。正常进入地图后继续保留真实 POI 身份去重。

这些过滤规则仅用于携程／小红书链接素材，不改变普通手动文字和图片输入的类别范围。

## 4. 状态与生命周期

复用现有进度与错误文本，区分“读取链接”“下载图片 n/N”“模型理解”“合并同一地点、剔除餐饮和非地点名称”“地图查询”。笔记处理阶段按钮为“正在处理笔记…”。抓取过程中禁用重复发送／编辑，允许取消。模型开始前不显示“已发送到模型”。取得内容后保留原分享输入用于查看；解析使用正文和用户说明，而非让模型访问 URL。

失败保留输入与已有附件，提供原发送动作重试。图文模型部分失败沿用逐项重试，不重新抓取已完整取得的原帖，也不重复发送成功素材；链接素材不完整时不先查询部分结果。整理失败或取消只重试整理；若手动或自动默认城市变化，城市相关解析缓存失效、重新理解素材，但保留已下载文件。取消时不得发布未整理候选。取消、配置变化、旅行失效、清空使旧代次无效；晚到回调不得回填。切换旅行的控制器和缓存按会话隔离。

只有用户点击收藏才写地点池，不改排行程、不新建旅行。收藏成功清空整批来源／图文／候选，清理只针对已完成批次的图片 ID；失败保留选择和原幂等保存行为。进程死亡不恢复失效图片，提示重新输入，已有收藏不变。

## 5. UI 与版本

不新增导入页面、弹窗向导或按钮。仅修改输入占位／说明、20 张提示、读取进度、受限与部分结果提示。使用当前工作树 `design/easy-trip-v3.3.0.pen`，继承最新 v3.2 累积源；冻结已发布文件。Pencil 路径核验、原生保存／重开回读；相关窄屏大字测试仍必需。

开发版本 3.3.0/build26，数据库 schema11 不变。用户随后已授权真实模型验证，通过后安装手机、提交和推送；只有真实闭环通过才执行条件交付。未授权创建 Release 或标签。

3. 助手控制器：只在发送读取、读取失败不调用模型、20 图逐项流程、时间预算、取消晚到、失败重试、旅行隔离、收藏自动新一轮。
4. Debug/Release JVM、lint、APK 构建；自有隔离模拟器 UI 和原始两条公开链接读取专项。真实模型为用户授权的显式 opt-in 模拟器测试，单样例最多正文 1＋图片 6＋整理 1 共 8 次，不自动重试，导入接口禁止写入；普通测试不能触发付费调用或真实手机写入。超限保护测试成功不代表地图候选闭环通过。
