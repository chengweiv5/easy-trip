# Easy Trip v3.0 Agent 统一规划：智能录入地点

状态：2026-10-10 用户确认合并方向；规划整合稿，详细交互、接口与实施计划待评审，尚未实现。

技术细化：[v3.0 Agent 技术架构设计](2026-10-10-easy-trip-v3-agent-architecture-design.md)。它属于本统一规划，不新增版本主线；本版明确 Kotlin Runtime、Provider 直连与可选网关；设计待评审，尚未实现。

## 1. 版本决策与唯一入口

v3.0 的“发现城市”与原 v4.0 Agent 规划合并为同一条 Agent 能力主线，不再维护独立的 v4.0 开发规划。

- **用户发现、用户决定，Agent 负责录入。** 用户在携程、小红书、豆包、Bilibili 等渠道自行发现想去的地点，把名称、文字或图片交给 Easy Trip；Agent 整理信息、匹配地图地点，按用户指令收藏。
- **首个交付闭环改为智能录入地点。** 原 v4.0 的已有行程调整、创建旅行、冲突检查等能力保留为后续阶段，不因合并而丢弃，也不全部塞入 v3.0 首期。
- **复用一套受控业务能力。** 手动操作与 Agent 使用相同的查询、校验和保存规则，不让模型直接写数据库，也不以模拟点击 App 为主路径。
- **不以平台内容抓取为成立前提。** 只有链接时可在正常授权范围内尝试读取；读不到时保存来源链接并请用户补充文字或图片，不能编造内容。

本文是当前规划入口。[原 v4.0 文档与三张源图](../../archive/v4-agent/README.md)按原始内容冻结，用作架构参考和历史证据，不再是独立版本开发入口。原方案中的“先调整已有行程”、旧源码/数据库基线和旧版本号不覆盖本文的新顺序。

沿用原在线文档，不另建第二份规划：[Easy Trip Agent 规划（同一文档，版本与首期目标以最新整合说明为准）](https://bytedance.larkoffice.com/docx/MhG8dAiFHorRB9xPts1cLx9enuc)。

## 2. 合并对应关系

| 原规划内容 | 合并后的归属 | 范围边界 |
| --- | --- | --- |
| v3.0 自动发现一个城市的景点 | 调整为用户提供素材、Agent 智能录入 | 不自动判断“值得去”，不做全平台抓取承诺 |
| v4.0 手机 Runtime + 云端推理 | 作为内置 Agent 的复用架构建议 | 本版采用 Kotlin Runtime + DeepSeek 直连；模型协议与成本需实测，不是已接通 |
| TripCapabilities / 类型化工具 | 智能录入和后续操作共用的能力层 | 先实现地点查询、草稿、校验和受控收藏所需部分 |
| ChangeSet、授权、幂等、回执、受限撤销 | 保留安全原则，按录入范围细化 | 不把整天重排的全部机制作为最小录入闭环的前置工程 |
| 已有行程自然语言调整 | 后续阶段，保留原设计参考 | 复杂变更仍需预览、并发校验与事务提交 |
| 创建旅行、行程检查修复、语音 | 后续复用同一能力层 | 另行确定版本与验收范围，不自动承诺首期交付 |
| 外部 Agent / MCP | 保留扩展边界 | 入口尚待选择；配对、授权、设备可达性不能由 MCP 协议替代 |
| 云同步、后台管家、天气票务、支付预订 | 维持独立设计 | 不因本次合并扩大范围 |

统一的是产品方向、执行能力和规划入口，不是将旧分支全部代码或旧源码状态覆盖到当前主线。

## 3. 用户交给 Agent 的内容

| 输入 | 处理方式 | 缺口处理 |
| --- | --- | --- |
| 地点名称与城市 | 按关键词检索地图 POI | 同名或城市不明确时澄清 |
| 复制的攻略文字 | 提取用户指定的地点和备注 | 区分“所有提及地点”与“用户决定收藏的地点” |
| 截图、攻略配图 | DeepSeek 图片理解得到候选，再匹配地图；OCR 可选降级 | 错字、断行、圈选不清和背景文字不得直接变成收藏 |
| 分享链接 | 保留来源；可选地尝试正常读取 | 链接不等于全文；不可读时提示补充内容 |

系统分享接收与 App 内粘贴/选图是候选入口，具体优先级和 UI 待评审。并不保证四个平台都支持同一种系统分享载荷。

默认仅处理用户主动交付的素材，不读取其他 App 的历史、账号 Cookie、私密内容或持续监听屏幕。云端识别如需发送截图/文字，必须明确数据范围并取得相应同意；优先只发送任务所需片段。来自素材的指令只能被视作内容，不能替用户授权。

## 4. 首个闭环

示例指令：

> 把我圈出来的这三个地方收藏到杭州旅行，标签加“想去”。

1. 接收素材与指令，确定目标旅行和用户要求处理的范围。
2. 提取候选名称，保留原始片段、图片序号或来源链接；此时不写地点池。
3. 通过地图搜索匹配 POI，得到标准名称、地址、坐标和稳定标识。
4. 展示已匹配、待澄清、已收藏和未找到的项目；只询问真正阻塞录入的歧义。
5. 首期统一展示结构化草稿，逐项勾选并确认后才提交；明确文字指令也不能跳过本地确认。仅“帮我看看”或分享素材本身不构成收藏授权，具体确认 UI 待评审。
6. 由受信任应用代码保存，回读真实结果后展示“已收藏 / 已存在 / 未保存”，地图和地点池显示同一份数据。
7. 提供撤销本次录入；若地点后来被编辑、加入行程或产生费用等关联，不静默删除，转为冲突说明或受控恢复。

Agent 不自主推荐、排序取舍、安排日期，也不顺便收藏图中其他地点。未找到坐标的素材可作为待处理草稿，不能冒充已收藏的地图地点。

## 5. 执行边界与拟议工具

本版采用“手机执行、云端推理”：原生 Kotlin + Coroutines/Flow 的轻量 Runtime，Room 保存状态；OkHttp + kotlinx.serialization 实现模型协议。`ModelPort → ProviderAdapter` 首期直连 DeepSeek Chat Completions（`deepseek-flash`）；用户配置 provider、Base URL、API key、model 即可，不要求另备网关。个人 key 由设备 Keystore 支持的加密存储保护，不能嵌入 APK。网关仅为未来共享凭据、账号与额度治理的可选扩展。首期不建设外部 Agent/MCP 入口，能力接口保留可复用边界。

DeepSeek 官方文档已确认图片和工具调用；设计优先截图直接输入，OCR 不是前置条件。默认显式关闭 thinking 做简单录入；以后开启时必须保留 reasoning_content 等续接字段。账号权限、具体 endpoint、“图片 + tools”组合和运行成本尚未实测，不能将文档能力当作接通。详细协议与凭据边界以技术架构为准。

以下只是待评审契约，不代表已有可调用 API：

| 能力 | 作用 | 写入边界 |
| --- | --- | --- |
| 读取目标旅行 / 已收藏地点 | 确定 tripId、已存在 POI 与作用范围 | 只读，最小上下文 |
| 解析用户素材 | 生成候选及来源证据 | 只写导入草稿，不决定收藏 |
| 搜索地图地点 | 按名称、城市和必要地址寻找 POI | 不自动保存；模型不能生成可信坐标 |
| 修改与校验导入草稿 | 记录用户选择、匹配结果、备注、标签 | 无坐标、越界和歧义以结构化状态返回 |
| 应用导入 | 按本地授权写入地点池并返回回执 | 由受信任执行器调用；模型不签发授权 |
| 撤销本次导入 | 撤销回执中本次新建、且未被后续修改的内容 | 不删除此前已存在地点或覆盖后续编辑 |

新增地点与其来源/备注/标签/分类作为一致的保存单元；确认选中的批次在同一 Room 事务提交。重复项保留已有内容，待澄清项不进入提交集合；任一新建项校验或写入失败时该选中批次整体回滚。回执逐项区分新建、已存在及未提交，不能仅以助手一句“全部完成”判定。

同一导入请求的重试须幂等；重复地点默认不覆盖已有备注、标签和分类。一次导入与另一次用户明确提交的导入应能区分，不能只根据相同文字永久拦截。

## 7. 原 v4.0 安全设计如何复用

- 查询、草稿、正式写入分离；不暴露任意 SQL、脚本执行或无边界工具。
- 正式写入必须验证目标旅行、用户选择、POI 和授权；模型工具调用不能跳过高德或云端数据门控。
- 根据持久化回执和数据库回读展示结果；超时、取消和进程重启后不重复收藏。
- 撤销只针对本次修改，保护原有内容和后续用户编辑。
- 云端仅接收最小上下文；任务日志默认不留完整旅行或素材正文，日志策略另行细化。
- 不把联网搜索结果、POI 描述、截图文字或备注中的指令当成用户授权。
- 原有触屏操作和已保存数据不依赖 Agent 在线；入口、云调用、写工具需要独立降级。

旅行级 editRevision、整份行程 ChangeSet 原子提交及路线草稿隔离，仍是后续行程调整阶段的重要参考；录入阶段采用何种最小冲突检测机制需要详细设计，不在本次规划合并中伪称已经决定或实现。

## 9. 验收门禁

- 用户指定的地点才进入收藏范围；分享素材本身不越权写入。
- 名称歧义、OCR 错字和无坐标明确阻塞对应项目，不编造。
- 链接不可读仍能使用用户提供的文字/图片完成主路径，并保留来源缺口。
- 同旅行重复 POI 不重复新增，不静默覆盖原备注/标签。
- 超时重试、重复点击、取消、进程重启与事务故障均能恢复准确状态。
- 回执、地点池和地图一致；待处理项目不被算作已收藏。
- 撤销不影响原有地点、后续编辑及关联行程/费用。
- 真实设备上的分享接收、媒体权限、隐私门控和前后台行为通过专项测试。
- 详细规划、Pencil UI 设计和实施计划完成各自评审后再开发；本次仅完成规划与技术设计，不升级 App 版本、不修改 schema、不发布或安装。
