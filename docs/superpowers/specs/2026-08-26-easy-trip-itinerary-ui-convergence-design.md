# Easy Trip 行程内容族 UI 收敛设计

日期：2026-08-26

## 1. 目标

在已完成的工作台壳层内，将单日行程、全程行程、行程项和 RouteLeg 收敛为紧凑时间线视觉语言。

本阶段减少常驻操作按钮和厚重卡片，使一屏展示更多有效行程信息，同时保持现有排序、编辑、跨日移动、删除、路线计算、失败恢复和全程只读语义。

## 2. 已确认决策

### 2.1 行程信息密度

采用紧凑时间线：

- 地点名称、到达时间和停留时长为主信息。
- 行程项编辑操作收进 `···` 菜单。
- 排序拖动保留独立拖动手柄。
- RouteLeg 是地点之间的轻量连接段，不使用厚重独立卡片。
- 单日行程可编辑，全程行程只读。

### 2.2 行程项菜单

`···` 菜单包含：

1. 编辑时间与停留时长。
2. 移动到其他日期。
3. 删除行程项。

菜单只派发现有 action，不持有编辑状态。删除继续进入现有二次确认流程。

### 2.3 RouteLeg

- 正常状态显示交通方式、预计时间和距离。
- 计算中显示小型进度指示和“正在计算路线”。
- 等待联网显示状态图标和简短说明。
- 失败显示错误原因和“重试”。
- 点击正常 RouteLeg 进入现有交通方式编辑流程。
- 点击“重试”只重试当前路段。

### 2.4 空状态

采用统一简洁图标插画：

- 使用 Compose 或矢量资源。
- 统一 Forest Sage 配色、线条粗细和尺寸层级。
- 不追求 Pencil 逐路径复刻。
- 插画只辅助状态识别，不挤压主要操作。

## 3. 范围

### 3.1 本阶段包含

- 单日行程时间线。
- 行程项视觉结构和操作菜单。
- 拖动手柄与菜单触控区域。
- RouteLeg 正常、计算中、等待联网和失败状态。
- 当天空态和没有旅行日的空态。
- 全程行程的只读时间线。
- 长地点名、长地址和长错误文案的常规竖屏布局。
- 现有编辑、移动、删除、交通方式和重试流程的 UI 接线回归。

### 3.2 本阶段不包含

- 工作台壳层、TopBar、搜索、地图控件或 Sheet 状态机重做。
- ViewModel、Repository、Room schema、路线 generation 或权限流程重写。
- 395/396dp 临界跳变、280dp 小窗、横屏、分屏或 2× 字体专项适配。
- 搜索与地点池页面族的 `＋` 和 `···` 改造。
- “更多”旅行级菜单改造。
- Mate 60 Pro 逐项即时验收；真机验收统一留到候选批次。

## 4. 信息架构

### 4.1 单日行程

```text
日期导航 │ 当天时间线
         │
         │ 09:30  灵隐寺                 ⋮
         │        停留 2 小时
         │
         │        步行 · 12 分钟 · 850 米
         │
         │ 12:00  知味观                 ⋮
         │        停留 1 小时
```

左侧日期导航继续提供：

- 全程。
- 按序排列的旅行日。
- 新增旅行日。

右侧时间线按当前 preview order 组合行程项与相邻 RouteLeg。

### 4.2 全程行程

- 按日期分组。
- 复用相同的地点与 RouteLeg 只读视觉 primitive。
- 不显示拖动手柄。
- 不显示行程项 `···` 菜单。
- 不显示修改交通方式入口。
- RouteLeg 只展示状态与路线摘要，不允许编辑。
- 不使用多层厚重卡片嵌套。

## 5. 组件边界

### 5.1 ItineraryItemRow

职责：

- 展示拖动手柄。
- 展示到达时间、地点名称、停留时长和必要的次要信息。
- 展示 `···` 菜单入口。
- 展示收藏地点失效等既有异常状态。
- 提供排序手势和无障碍上移/下移动作。

非职责：

- 不持有编辑草稿。
- 不持有跨日移动状态。
- 不执行删除。
- 不计算路线。

建议接口保持事件化：

```kotlin
@Composable
fun ItineraryItemRow(
    item: ItineraryItemUi,
    index: Int,
    count: Int,
    onPreview: (Int) -> Unit,
    onCommit: (Int) -> Unit,
    onOpenMenu: () -> Unit,
    modifier: Modifier = Modifier,
)
```

若现有 overlay 架构更适合由父层保存菜单目标，行组件只上报当前 item id，不在行内保存业务状态。

### 5.2 ItineraryItemMenu

职责：

- 显示“编辑时间与停留时长”。
- 显示“移动到其他日期”。
- 显示“删除行程项”。
- 保持删除危险语义。

菜单操作映射到现有 action：

- `RequestTiming(itemId)`
- `RequestCrossDay(itemId)`
- `RequestDelete(itemId)`

菜单关闭不改变行程数据。删除仍由现有确认状态和确认操作完成。

### 5.3 RouteLegRow

职责：

- 展示两个地点之间的连接关系。
- 展示 RouteLeg 当前状态。
- 正常状态进入交通方式编辑。
- 失败状态派发当前 leg 的重试。

非职责：

- 不持有 mode editor。
- 不发起网络请求。
- 不更新 Repository。
- 不影响其他 RouteLeg。

建议保持现有事件接口：

```kotlin
@Composable
fun RouteLegRow(
    leg: RouteLegUi,
    onMode: () -> Unit,
    onRetry: () -> Unit,
    modifier: Modifier = Modifier,
)
```

### 5.4 DayItineraryTimeline

职责：

- 按顺序渲染地点行和相邻 RouteLeg。
- 管理列表滚动、底部安全间距和空态。
- 将排序、菜单和 RouteLeg 事件转发给父组件。

非职责：

- 不持有编辑弹窗状态。
- 不持有跨日移动状态。
- 不执行路线请求。

当前 `DayItineraryContent` 可演进为时间线容器；不因命名优化重写状态接口。

### 5.5 WholeTripItineraryContent

- 复用只读地点行和 RouteLeg 视觉 primitive。
- 继续按 `WholeTripDayUi` 渲染。
- 保持日期分组、空日和整段滚动。
- 不接收编辑类 action。

## 6. 视觉规则

### 6.1 行程项

- 地点名称：Inter 15–16sp，Semibold。
- 到达时间：Primary 色，作为时间线定位信息。
- 停留时长、地址和辅助信息：Muted 色，12–13sp。
- 地点名称常规竖屏最多两行；不能挤出拖动手柄或菜单。
- 地址最多两行；在空间不足时优先省略地址，不压缩操作区。
- 行程项使用轻量 Surface 或透明背景，不使用明显阴影。
- 行与行之间通过间距、时间线和轻分隔表达层级。

### 6.2 操作区

- 拖动手柄和 `···` 图标视觉尺寸 20–22dp。
- 密集场景触控区 40dp。
- 两个触控区不重叠，间距至少 4dp。
- 列表中不常驻红色删除按钮。
- Danger 色只用于菜单中的删除项和删除确认层。

### 6.3 RouteLeg

- 默认背景透明或使用低对比 Surface。
- 连接线使用 Primary/Secondary 的低对比颜色。
- 正常：交通方式为主要文字，时长和距离为次要文字。
- 计算中：显示进度指示与“正在计算路线”。
- 等待联网：显示状态图标与“等待联网”。
- 失败：错误原因最多两行，并显示明确“重试”。
- 四类状态不能只靠颜色区分。
- RouteLeg 高度由内容决定，不写固定卡片高度。

### 6.4 时间线

- 地点行与 RouteLeg 的中心线对齐。
- 拖动预览只提升当前地点行，不改变其他行的视觉语义。
- 时间线不能遮挡文本或操作区。
- 正常竖屏内不发生横向滚动。

## 7. 空态

### 7.1 当天无行程

包含：

- 简洁图标插画。
- “第 N 天 · 暂无行程”。
- 简短说明。
- “从地点池添加”主要操作。

### 7.2 没有旅行日

包含：

- 简洁图标插画。
- “暂无旅行日”。
- 简短说明。
- “新增旅行日”主要操作。

空态不得新增隐式创建日期或绕过现有流程的快捷行为。

## 8. 交互规则

### 8.1 排序

- 长按拖动手柄开始排序。
- 仅手柄区域发起拖动；点击地点主体或菜单不触发排序。
- 保留无障碍“上移/下移”动作。
- 拖动阈值使用 dp 转 px，不直接使用原始 px 常量。
- 排序预览和提交继续派发既有 action。

### 8.2 行程项菜单

- 点击 `···` 打开当前项菜单。
- 菜单打开时再次点击外部区域或返回键只关闭菜单。
- 点击编辑、移动或删除后关闭菜单并进入现有流程。
- 提交中状态沿用现有返回和 dismiss 锁定策略。

### 8.3 RouteLeg

- 正常 RouteLeg 点击进入交通方式编辑。
- 计算中和等待联网状态不触发 mode editor，除非现有业务规则明确允许。
- 失败状态“重试”只派发 `Retry(legId)`。
- RouteLeg 其他区域不误触相邻地点菜单。

### 8.4 全程行程

- 不提供排序。
- 不提供行程项菜单。
- 不提供交通方式编辑。
- 不提供移动和删除。
- 保留可阅读的 RouteLeg 状态。

## 9. 状态与数据流

本阶段保留现有单向状态流：

```text
DayItineraryUiState / WholeTripDayUi
    ↓
DayItineraryTimeline / WholeTripItineraryContent
    ↓ user event
DayItineraryAction
    ↓
DayItineraryViewModel
    ↓
existing service / repository
```

UI 组件不直接访问 Repository。现有 generation、Job cancellation、失败保留草稿、删除确认和跨日移动状态不变。

菜单可以新增纯 UI 选择状态，但不能成为业务草稿的第二事实来源。当前正在编辑、移动或删除的 item id 继续由现有 ViewModel 状态决定。

## 10. 错误与恢复

- 编辑时间失败：保留编辑草稿和错误信息。
- 跨日移动失败：保留目标日和错误信息。
- 删除失败：保留确认层和错误信息。
- RouteLeg 失败：保留错误原因和当前 leg 的重试入口。
- 等待联网：不把状态伪装为失败，不显示无效重试。
- 地点失效：继续显示可识别的异常说明，不导致列表崩溃。

## 11. 可访问性

- 拖动手柄提供明确 `contentDescription`。
- 菜单按钮提供“更多行程项操作”描述，并包含地点名称上下文。
- 菜单项使用正确 Button/MenuItem 语义。
- 行程项保留“第 N 项，共 M 项”和上移/下移 custom action。
- RouteLeg 暴露交通方式和状态文字。
- 计算中使用 live region 或等效语义；进度指示不可成为唯一状态来源。
- 全程视图不暴露编辑类 action。

## 12. 自动化验收

### 12.1 行程项

- 时间、地点名称、停留时长和菜单可见。
- 拖动手柄与菜单触控区不重叠。
- 长地点名不挤出时间、拖动手柄或菜单。
- 菜单项与 `RequestTiming`、`RequestCrossDay`、`RequestDelete` 一一对应。
- 删除继续进入二次确认。
- 排序手势和无障碍上移/下移动作保持。

### 12.2 RouteLeg

- Ready、Calculating、WaitingForNetwork、Failed 均有文字或语义标识。
- 正常状态显示交通方式、预计时间和距离。
- 失败状态显示错误原因和重试。
- 重试只携带当前 leg id。
- 修改交通方式只作用于当前 leg。
- 单路段失败不污染其他 RouteLeg。

### 12.3 单日与全程

- 单日保留编辑、排序、移动、删除和 RouteLeg 操作。
- 全程不出现 drag、timing、move、delete、mode 等编辑 action。
- 当天空态引导从地点池添加。
- 无旅行日空态引导新增旅行日。
- 长列表可滚动，末项不被 Sheet 底部遮挡。

### 12.4 状态恢复

- 保存失败保留草稿。
- 移动失败保留目标日。
- 删除失败保留确认层。
- 等待联网和失败状态语义不混淆。
- 返回键继续遵守现有 overlay 优先级。

### 12.5 门禁

每个实施批次至少运行：

- 行程映射和 ViewModel JVM 测试。
- `ItineraryEditingTest`。
- `ItineraryScopeRailTest`。
- `WholeTripItineraryContentTest`。
- 相关工作台 Compose tests。
- `lintDebug`。
- `assembleDebug` 和 `assembleDebugAndroidTest`。

候选批次运行：

- `V1ScenarioCatalogTest` 47/47。
- `V1FullUiAcceptanceTest` 47/47。

## 13. 人工验收

人工验收统一留到后续 Mate 60 Pro 候选批次，不作为每个小改的即时门禁。

重点状态：

- 半屏单日行程的信息密度。
- 展开态长行程滚动。
- 长地点名与长错误文案。
- 拖动手柄和 `···` 菜单的误触风险。
- RouteLeg 正常、计算中、等待联网和失败。
- 全程视图的只读层级。

阻断条件仍为功能/状态错误、崩溃、不可达、严重裁切或关键操作不可点击；小范围视觉差异进入后续统一裁决。

## 15. 完成定义

行程内容族 UI 收敛完成需满足：

- 单日行程采用紧凑时间线。
- 行程项只常驻拖动手柄和 `···` 菜单，不常驻编辑/移动/删除文字按钮。
- RouteLeg 四类状态清晰且不使用厚重卡片。
- 全程行程保持只读。
- 现有业务状态机、数据层和错误恢复语义不变。
- 聚焦自动化、静态门禁和 47 场景回归通过。
- 未决视觉细节进入统一真机验收，不被冒充为已验收。
