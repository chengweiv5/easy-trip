## 1. 用户目标与设计取舍

**已明确的目标**

- 用户在携程、小红书、豆包、Bilibili 等渠道自行发现地点；不依赖平台抓取。
- 助手把用户提供的地点快速标记到地图，用户判断是否收藏到当前旅行的地点池。
- 首版建立闭环；后续逐步增加通过 Agent 操作 App 的入口。
- 第一版必须包含 UI 设计，不把命令行探针当作产品。

**本稿建议**

1. 首版文字输入/主动粘贴，一次解析多个地点，点击「全部标记到地图」；不要求用户逐个录入。
2. 同一地点的多个 POI 全部保留为候选；不把地图搜索排名当作“值得去”的推荐。
3. 明确匹配的地点统一显示临时图钉；歧义、未找到和查询失败分别处理。用户可逐个确认，也可勾选或全选后进入批量核对，再明确确认收藏。
4. 使用入口放在当前旅行地图中，保留普通地点搜索；配置入口为 **App 全局设置 → 助手设置**，不是旅行设置，不另做全屏聊天首页。
5. 截图、系统分享接收、链接读取、自动备注/标签、Agent 撤销、行程/费用操作不进入本版。

“全部”指本次输入中可确认位置的地点，不是城市内全部景点，也不是让模型决定哪些地点值得去。批量限额、协议和事务方案是下文的工程设计建议，已按这些上限实现并完成小批专项验证，20项压力与多城市真实样本仍待扩展验证。

## 2. 完整闭环

`当前旅行地图 → 助手 → 城市+文字 → 模型理解 → 真实POI查询 → 地图候选 → 用户核对 → 确认收藏 → Room回读 → 地点池/地图同步`

示例：「把杭州的灵隐寺、河坊街、雷峰塔、西湖边的小院都标记出来」。

- 进入助手时绑定当前 `tripId`，标题持续显示目标旅行；不让模型选择旅行。
- 有明确的当前搜索城市则展示为可修改字段；旅行多城市、缺少城市、输入城市与已选城市冲突时要求用户确认，不把 GPS 当作默认答案。
- 本地为每个识别项生成稳定 itemId 和 A–T 展示编号，再有界查询全部可查询项；不是让用户先选一个再查。
- 无歧义匹配先标记。仅在合法坐标、城市范围和名称证据足以唯一确定真实 POI 时归为可收藏；搜索排名第一、模型确信或同名多个结果都不能直接消歧。多个候选进入单项核对，最多展示该项的 20 个真实 POI。
- 示例 A/B 已标记、C 有同名候选、D 未找到；A/B 可以先核对收藏，不被 C/D 阻塞。C1/C2 是 C 的临时位置对照，选定后仍保留 itemId=C。
- 选择某个候选只聚焦地图并显示确认卡，不保存。单个匹配也不能跳过确认卡。
- 单项/批量确认包括旅行、每个所选 POI 的名称、城市、地址、地图位置和分类。分类默认「其他」，可逐项通过既有五分类选择器修改；图稿中的「景点」是用户已选示例，不代表探针验证了分类写入。图稿地址与底图只用于示意，不是地点资料或实测结果。
- 勾选和「全选可收藏的 N 个」只修改选择集，不保存；再次取消勾选即移出。歧义、未匹配、查询失败、缺坐标和已有收藏不能被全选。所选为 0 时不提供提交收藏按钮；选择后仍须打开核对页并点击「确认收藏 N 个地点」。
- 「确认收藏」是可信本地 UI 事件。即使原文写了“帮我收藏”，模型也不能替代这次确认。
- 保存后只增加地点池记录，不加入行程、不安排日期、不新增费用。收到本地持久化成功结果后才显示成功回执。
- 已有同 POI 返回「已在地点池」，不覆盖备注、标签、分类或行程关系。
- 回执只报告本次实际新增/已存在结果。未选和未解决的项留在本批；「继续处理剩余项」不重新查询已完成结果。改输入建立新草稿前先确认放弃未收藏内容。

## 4. 技术收敛

### 4.1 模块职责

| 模块 | 责任 | 不承担什么 |
| --- | --- | --- |
| `PlaceAssistantViewModel` | StateFlow、当前旅行/城市/输入、地图和面板状态 | 不直接执行 SQL 或解释原始模型 JSON |
| `AgentRuntime` | 有界模型轮次、取消、工具 schema 校验、调用注册表 | 不产生收藏授权，不持有 Activity/MapView |
| `ModelPort / DeepSeekAdapter` | HTTPS 请求、鉴权、协议解码、限额与脱敏 | 不读取地点池、不把工具文本当 UI 真相 |
| `PlaceQuery` | 通过当前高德隐私会话查询真实 POI | 不让模型提供坐标或保存地点 |
| `PlaceImport` | 确认快照校验、事务、去重、回读结果 | 不自行重新搜索或重新请求模型 |
| 既有地图宿主/Room repositories | 渲染候选层和收藏层、同一数据事实来源 | 不创建第二个地点池 |

保持在现有 `:app` 内，先形成小而明确的接口，不预建多 Agent、微服务或单独 Gradle 模块。

### 4.2 首版模型协议

- 首个 Provider 为已实测的 DeepSeek `deepseek-flash`，用户提供 Base URL / Key / model 即可，网关非必需。
- 首版非流式、thinking disabled。工程参数建议：一次解析模型请求 + 最多一次可选总结，每请求 45 秒，整批 90 秒；不自动重试。取消/超时保留已完成项，用户手动重试未完成项时创建新 runId/item generation。
- 输入上限 2,000 字符、每批最多 20 个地点、查询词 100 字符、城市 50 字符；输出预算建议 4,096 tokens，截断/不完整 JSON 视为失败，禁止执行半份列表。这些是待实测参数，不沿用单地点探针的 512 tokens 作为生产定值。
- 建议新增首版只读批量工具 `search_place_batch(items[], overflow)`：模型一次给出有序 query/city/sourceSpan 列表，应用验证后分派现有 `PlaceQuery`；itemId 由本地分配，不信任模型生成的编号。一个响应仅接受一次完整批量调用，拒绝混合未知工具或多个独立调用，避免无界 Agent 循环。超过 20 项/overflow 时显示 A33，不静默截断或先查前 20 个。
- 应用有界调度每项最多一次真实搜索（建议并发上限 2、单项 15 秒、每项最多 20 个 POI）；模型不是每个地点再调用一次。歧义只影响对应项，用户修改单项名称/城市才重查该项。现有 `search_places` 单地点探针不等于新批量协议已通过。
- 解析完整 JSON 后执行白名单/schema/长度检查。未知工具、缺参数、非法城市上下文、超限调用均不执行。
- 查询返回本地生成的 `candidateId`、真实 POI 标识/名称/地址/坐标与可用城市字段。最终文字可用于解释，但不能宣称模型说“已标记”就代表地图已完成。
- 实际查询成功且候选可渲染即可走本地预览；可选总结仅接收最小匹配摘要，其超时不抹掉已验证候选。UI 状态由本地事件决定。禁止通用 URL、Shell、SQL 和模型直接收藏工具。
- 输入、地点描述与工具输出均为不可信内容；嵌入的“忽略规则/直接收藏”等不能改变权限。

### 4.3 数据与事务

建议的核心记录：

| 记录 | 关键字段 | 生命周期 |
| --- | --- | --- |
| `PlaceIntakeDraft` | draftId/runId/tripId/defaultCity/input/items/selectionRevision/selectedIds | 当前旅行会话内存；不持久保存原文 |
| `PlaceIntakeItem` | itemId/query/city/sourceSpan/generation/status/candidateRefs/selectedPoi/category | 每项独立：查询中/待城市/歧义/未找到/失败/可收藏/已存在 |
| `VerifiedPoi` | candidateId/poiId/name/address/point/city metadata/query generation | 来自本次真实查询，不接受模型重写坐标 |
| `ImportConfirmation` | operationId/tripId/draftId/selectionRevision/sorted item+POI+category+generation/payloadDigest | 本地点击生成，不发送给模型 |
| `ImportReceipt` | operationId/tripId/itemResults[]/payloadDigest | 与本次所有正式新增同一 Room 事务写入 |

首版草稿不保证进程重启恢复，关闭面板在当前会话保留；退出旅行/清空需提示。**收藏记录和回执必须持久保存。** 与早期“所有任务与素材持久化”的完整架构相比，这是有意收敛。

已新增最小回执表及 schema 10→11 迁移；表内不保存输入、Key 或模型长文本。`operationId` 唯一，同一 ID 不同 digest 必须拒绝。schema11与10→11迁移已实现；旧表/字段保留、失败回滚及磁盘重开回读已测试。

确认保存的单一事务（单项是列表长度为 1 的同一能力）：

1. 核验目标旅行、确认的选择版本、所有所选项 generation/digest、有效坐标与地图预览状态。背景的未选项完成查询不使未变的确认失效；选择、目标、任一所选 POI/分类/城市改变必须重新核对。
2. 已有 operationId 回执则核对 digest 并直接回读。所选列表内按 `tripId + poiId` 去重；两个原文项命中同一 POI 时只允许一个可选代表，其他项注明“同地点”。提交时再次检查并发产生的已有记录，将其作为 AlreadySaved 回执，不改旧内容。
3. 所选的新地点、逐项用户确认分类和整批回执作为一个原子单元写入；任一写失败全部回滚，未选/未解决项不参加事务。并发已有项不算新增，不把整批数冒充新增数。
4. 收藏 Flow 刷新后将候选转换为既有收藏图标；不能只换图标而未写数据库。

现有 `RoomSavedPlaceRepository.save()` 已有事务去重和缺坐标校验，但它只保存默认分类；不能简单 `save` 再单独 `updateCategory` 冒充上述原子契约。实施时把最小 import 事务封装到共享业务能力，手动和 Agent 保持相同规则。

未返回 cityAdCode/cityCode 时保留缺失值，不从模型补造；城市名称与用户选择不一致时重新确认。首版不依赖路线规划，因此没有路线城市码不是收藏失败的理由。

### 4.4 取消、过期和重启

- 提交新输入或切旅行使旧 run 和确认失效；回调必须匹配 runId、item generation 和 privacy generation。更改本批默认城市只重查依赖默认城市的项；单项改城市只重查该项。其他明确城市的结果保留，若所选项改变则重新确认。
- 输入城市与默认城市冲突、实际 POI 跨城时仅该项进入待城市确认；可以按项采用输入城市或改城市，不猜定位，也不连带阻塞已明确的项。
- 取消搜索只取消未完成任务并屏蔽迟到结果，保留已完成标记和选择，已有收藏不受影响。已取消/失败的项可单项或一键“仅重试失败项”，无后台自动重试。
- 保存中禁止双击或改目标；该事务不等同可取消的模型任务。进程中断后按回执/现有地点恢复结果，不自动创建另一笔收藏。
- 高德同意被撤销时，停止查询并清除候选；重新同意后重新搜索，不重用旧 session token。
- 选中候选缺坐标、地图未加载成功、目标旅行失效时不开放确认；模型文字不会绕过这些门禁。
- 本版没有「撤销导入」按钮。用户可以走既有地点编辑/删除流程；后续再实现有版本与引用保护的 Agent 撤销，不能把级联删除包装成普通撤销。

## 5. 助手设置、Provider 配置与隐私

**2026-10-11 用户确认命名：统一使用「助手设置」。** 路径为 **App 设置 → 助手设置**，不是旅行设置；配置一次，所有旅行共用。当前页面只展示「模型服务」分区，未来其他助手设置在同一页面扩展，不提前放置无效选项。未配置/连接失败的引导与返回文案统一指向「助手设置」；从旅行进入时完成后返回原旅行继续操作。

- 用户配置直连 Provider，不要求部署云端服务；“可配置”不等于首版保证兼容任意 Provider。
- Base URL 只接受 HTTPS，禁止 userinfo/query/fragment；确定性拼接聊天路径，禁止鉴权请求跟随跨源重定向。修改 host、模型或 Key 后必须重新测试。
- Key 放在本机 Keystore 支持的加密存储，排除云备份、日志、崩溃附件和 UI 截图；页面默认掩码，只有显式操作临时显示。
- 测试连接发送固定、无旅行信息的最小文本与工具定义，验证响应及工具 JSON；无自动执行真实 POI。测试前明示一次调用和费用。
- 只有文字响应没有有效工具结构，显示“连接成功但工具能力不可用”，不能启用助手。HTTP 401/403、429、超时、5xx 分别给可理解原因；不展示完整请求或响应中的秘密。
- 新配置验证成功后才替换旧配置；进入新 host 的第一次真实发送再次展示数据范围。
- 发送本次输入、必要城市；可选总结才回传最小 POI 匹配摘要。不发送完整旅行、费用、位置历史、账号 Cookie 或本地确认凭据。Key 只在请求鉴权头中使用，不放到模型消息里。
- 不监控剪贴板，不读取其他 App，不抓取用户粘贴链接。只有链接时要求补充地点文字。

## 6. 验收标准

**已通过的可行性证据**见 [地图闭环验证](../../testing/v3.0-agent-place-map-loop-validation.md)。这不等于下列产品验收已经通过。

实施完成后至少验证：

1. 1/4/20 个文本地点、超限不截断、无城市/单项城市冲突、多 POI/空结果/缺坐标/跨城结果；稳定编号及重复 POI 归并。
2. 部分成功时标记与选择保留；取消、仅重试失败、改单项城市、切旅行、高德撤权与迟到回调不会覆盖其他项或自动保存。
3. 未确认 0 写入；勾选/全选/取消勾选 0 写入；无法确认的项不能入选；单项和批量连续点击均幂等，AlreadySaved 不覆盖既有内容。
4. 所选新地点、逐项分类和批量回执同事务；任一写失败整批回滚；并发出现已有项回执准确；进程终止后回读真实结果。
5. 清除搜索层后收藏图钉仍存在，重启 App 后相同 POI/位置/分类仍存在。
6. 无模型配置、401/429/超时、工具格式错误均可恢复；普通搜索和旧页面不受阻。
7. Provider URL/重定向/日志/备份/截图保护的安全测试；网络请求预算可观测。
8. 320dp、键盘、双倍字号、TalkBack、明暗/既有配色与地图面板遮挡的设备回归。
9. 原有旅行、地点编辑、行程、费用、分享等回归；历史未通过项继续单列。

“快速”首版先以城市复用、一次批量输入、明确项先呈现和取消可用衡量。此前两个单地点耗时样本不能代表批量表现；实施联调需验证列表召回、每项定位正确性、并发/超时预算和分阶段耗时，不能把单地点成功外推为批量已通过。
