# Easy Trip 一期设计

## 1. 产品目标

Easy Trip 是一款 Android 旅行规划工具。用户以地图为核心界面，搜索并收藏地点，再把收藏地点手动编排到每天的行程中，通过真实路线预览单日或整段旅行。

一期不提供 AI 推荐或自动生成能力。产品价值在于让用户直观、自由地组织地点和路线，并确保同一地点可以在同一天或不同日期中重复安排。

## 2. 一期范围

### 2.1 包含

1. 本地旅行的创建、重命名和删除；
2. 有日期旅行与无日期草案；
3. 旅行日的追加、前后插入、拖动排序和指定删除；
4. 自驾游与非自驾游设置；
5. 高德地图展示与 POI 搜索；
6. 旅行内地点收藏、备注、自定义标签和标签筛选；
7. 从地点池向任意旅行日重复添加地点；
8. 行程项日内排序、跨日移动和删除；
9. 可选到达时间和停留时长；
10. 交通方式规则推荐和逐路段覆盖；
11. 真实路线、距离和预计耗时；
12. 自动局部重算、失败重试和恢复联网后续算；
13. 单日地图预览和全程地图预览；
14. 本地离线查看已保存的数据与成功路线。

### 2.2 不包含

- AI 推荐或自动生成行程；
- 登录、云同步和多设备恢复；
- 多人协作；
- 分享和导出；
- 自定义地图落点；
- 酒店、门票或餐厅预订；
- 实时导航；
- 费用管理；
- iOS 或其他跨平台客户端；
- 自动优化地点顺序；
- 后台持续定位。

## 3. 核心概念

### 3.1 旅行与旅行日

旅行有两种时间模式：

- **有日期旅行**：设置起始日期，旅行日按顺序映射到具体日期；
- **无日期草案**：只包含若干“第 N 天”，后续可补充起始日期。

旅行日是稳定的内容容器。用户可以：

- 在当前日前后插入一天；
- 在末尾追加一天；
- 拖动整天调整顺序；
- 删除指定的一天。

移动旅行日时，其内部的行程项和日内路段整体跟随。对于有日期旅行，日期由 `startDate + position` 动态计算；移动或删除旅行日后，日期按新顺序重新分配。

### 3.2 地点收藏与行程项

地点分为两层：

- **收藏地点**：表示这次旅行中可能要去的地点，保存高德 POI 摘要、备注和标签；
- **行程项**：表示某一天中的一次具体安排，引用一个收藏地点。

收藏地点只属于单次旅行，没有全局收藏。同一个高德 POI 在同一次旅行中只收藏一次，但可以创建任意多个行程项，因此可在同一天或不同日期重复出现，例如连续住宿的酒店或每天多次返回的地点。

删除某个行程项只移除该次安排。删除已被引用的收藏地点前必须提示用户，并在确认后删除其全部行程项及受影响路段。

### 3.3 路段

同一天内每两个相邻行程项之间形成一个路段。不同旅行日彼此独立，不生成跨天路段。

路段保存：

- 起点和终点行程项；
- 推荐交通方式；
- 用户覆盖的交通方式；
- 计算状态；
- 距离、预计耗时和路线轨迹；
- 错误信息和版本。

实际交通方式为用户覆盖值优先，否则使用推荐值。路段只属于当前邻接关系：顺序改变后，不再相邻的路段被删除，新邻接关系创建新路段。

## 4. 交通方式推荐

旅行设置为以下一种模式：

- **自驾游**：新路段推荐驾车；
- **非自驾游**：按两地点的直线距离推荐：
  - 距离不超过 1 公里：步行；
  - 距离超过 1 公里：打车（包括超过 20 公里的路段）。

已有灵活旅行的旧公交推荐在打开数据库时更新为打车；无手动覆盖的路段重新计算，手动覆盖的实际方式和结果保持。

用户可以逐路段覆盖推荐方式。用户覆盖值不会被自动推荐覆盖。增删或移动行程项所产生的新路段重新执行推荐规则。

产品中的“打车”和“自驾”都使用高德驾车路线计算，但保留不同的文案和图标。

## 5. 信息架构与用户流程

### 5.1 旅行列表

首页展示本地旅行列表，支持新建、打开和删除旅行。

创建旅行时填写：

- 旅行名称；
- 时间模式：起始日期加旅行日，或无日期草案；
- 初始旅行日数量；
- 出行模式：自驾游或非自驾游。

### 5.2 旅行工作台

旅行工作台采用“地图为主、底部抽屉”的结构：

- 顶部包含返回、旅行名称、搜索入口和预览范围；
- 地图占据主体；
- 底部抽屉在“地点池”和“每日行程”之间切换；
- 抽屉支持收起、半展开和全展开。

地图始终保留，使搜索、收藏、编排和路线反馈尽量在同一上下文完成。

### 5.3 地点池流程

1. 用户搜索高德 POI；
2. 搜索结果同时显示在地图和抽屉中；
3. 用户收藏地点；
4. 用户可添加备注和自定义标签；
5. 用户可按标签筛选地点池；
6. 用户从地点池将地点添加到指定旅行日；
7. 每次添加创建独立行程项，不限制重复次数。

一期仅支持高德 POI，不支持长按地图创建自定义地点。

### 5.4 每日行程流程

用户选择一个旅行日后可以：

- 从地点池添加地点；
- 拖动调整日内顺序；
- 将行程项移动到其他旅行日；
- 删除一次安排；
- 设置可选到达时间和停留时长；
- 覆盖某个路段的交通方式。

拖动过程中不发起路线请求；用户松手并确认新顺序后，系统保存编排并异步重算受影响路段。

### 5.5 地图展示

地图支持以下模式：

- **地点池模式**：展示当前旅行的全部收藏地点；
- **单日模式**：展示当天按顺序编号的行程项、真实路线、距离和耗时；
- **全程模式**：叠加所有旅行日的路线，每天使用不同颜色。

重复地点不能被合并成单次安排。点击标记时，应展示对应的日期和出现顺序；同一坐标存在多个行程项时，用户可以查看该坐标对应的全部安排。

## 6. 数据模型

### 6.1 `Trip`

- `id`
- `name`
- `timeMode`：有日期 / 无日期
- `startDate`：有日期模式下存在
- `travelMode`：自驾游 / 非自驾游
- `createdAt`
- `updatedAt`

旅行天数由关联的 `TripDay` 数量得出，不冗余存储。

### 6.2 `TripDay`

- `id`
- `tripId`
- `position`

`id` 是稳定身份，`position` 决定“第 N 天”和具体日期。

### 6.3 `SavedPlace`

- `id`
- `tripId`
- `amapPoiId`
- `name`
- `address`
- `latitude`
- `longitude`
- `note`
- 地图展示所需的 POI 摘要

同一旅行内的 `amapPoiId` 唯一。

### 6.4 `Tag` 与 `SavedPlaceTag`

`Tag` 包含：

- `id`
- `tripId`
- `name`

同一旅行内标签名称唯一。`SavedPlaceTag` 保存地点与标签的多对多关系。

### 6.5 `ItineraryItem`

- `id`
- `tripDayId`
- `savedPlaceId`
- `position`
- `arrivalTime`：可选
- `stayDurationMinutes`：可选

同一 `savedPlaceId` 可以被任意数量的行程项引用。

### 6.6 `RouteLeg`

- `id`
- `tripDayId`
- `fromItemId`
- `toItemId`
- `recommendedMode`
- `selectedMode`：可选
- `status`：等待联网 / 等待计算 / 计算中 / 成功 / 失败
- `distanceMeters`
- `durationSeconds`
- `polyline`
- `errorCode`
- `version`
- `updatedAt`

实际交通方式为 `selectedMode ?? recommendedMode`。

## 7. Android 架构

一期使用单体 Android App，不为跨平台或假想规模拆分 Gradle 多模块。

建议技术栈：

- Kotlin；
- Jetpack Compose；
- Navigation Compose；
- ViewModel、StateFlow 和 Coroutines；
- Room；
- 高德地图 Android SDK；
- 高德 POI 搜索与路线规划能力。

高德地图在 Compose 中的集成方式及各类路线 API 限制，应在正式功能开发前通过小型技术验证确认。

### 7.1 页面层

- `TripListScreen`：旅行列表和创建、删除操作；
- `TripWorkspaceScreen`：地图、搜索、地点池、每日行程和预览；
- `TripSettingsScreen`：旅行信息、时间模式、出行模式和旅行日结构。

复杂编辑优先使用对话框或底部弹层，不为每个操作创建独立页面。

### 7.2 领域层

- `TripService`：管理旅行和旅行日，计算显示日期；
- `PlaceService`：收藏 POI、编辑备注和标签、删除地点及引用；
- `ItineraryService`：添加、排序、跨日移动和删除行程项，维护邻接路段；
- `TransportModeRecommender`：执行纯规则交通方式推荐；
- `RoutePlanner`：映射产品交通方式、请求并保存路线结果；
- `RouteRefreshCoordinator`：异步计算等待中的路段并防止过期结果写入。

### 7.3 数据层

- `TripRepository`
- `SavedPlaceRepository`
- `ItineraryRepository`
- `RouteLegRepository`
- `AmapPlaceDataSource`
- `AmapRouteDataSource`

上层不得直接依赖高德返回模型。涉及行程顺序、旅行日顺序和邻接路段的写入必须在同一 Room 事务中完成。

## 8. 路线更新与并发

一次编排操作先在本地事务中保存新顺序，并同步完成以下变更：

1. 删除不再有效的路段；
2. 创建新邻接关系对应的等待计算路段；
3. 提交数据库事务；
4. 异步计算新路段。

例如从 `A → B → C` 中删除 `B`，事务删除 `A → B` 和 `B → C`，并创建等待计算的 `A → C`。

每次路线请求携带路段 ID 和版本号。只有响应版本与当前数据库记录一致时才允许写入，避免用户连续编辑时旧响应覆盖新路线。连续请求可以取消；无法取消时必须忽略过期结果。

## 9. 错误处理与离线行为

### 9.1 POI 搜索

- 输入停止短暂时间后发起搜索；
- 新输入取消旧搜索，旧结果不得覆盖新结果；
- 搜索失败只影响搜索区域，不清空地图或地点池；
- 收藏时保存必要 POI 快照，后续打开旅行不依赖再次查询。

### 9.2 路线失败

每个路段独立显示等待、计算中、成功或失败状态。路线失败不影响行程项保存和继续编辑。

- 超时、断网等临时错误可手动重试；
- 恢复联网后自动继续等待联网的路段；
- 高德明确返回无路线时记录为业务失败，不无限重试；
- 公共交通无法规划时明确提示，用户可改选其他交通方式；
- 不伪造距离、耗时或路线。

### 9.3 离线能力

- 可离线查看旅行、收藏地点、行程和已成功缓存的路线；
- 可使用已有地点池继续编排行程；
- POI 搜索不可用；
- 新产生或失效的路段进入等待联网状态；
- 网络恢复后自动继续计算。

### 9.4 本地数据

Room 使用外键和事务保持引用完整。路线缓存无法解析时只丢弃该路段缓存并重新计算，不删除行程。

删除旅行、含内容的旅行日或被引用的收藏地点前必须明确确认影响范围。

## 10. 测试策略

### 10.1 单元测试

覆盖：

- 1 公里交通方式边界，以及超过 20 公里仍推荐打车；
- 自驾模式始终推荐驾车；
- 同一地点创建多个行程项；
- 日内增删、排序和跨日移动后的邻接路段变化；
- 插入、删除、移动旅行日后的日期计算；
- 用户覆盖交通方式的优先级；
- 旧路线响应不能覆盖新版本路段。

### 10.2 Room 集成测试

覆盖：

- 删除收藏地点及全部引用；
- 删除中间行程项并建立新邻接路段；
- 跨日移动行程项；
- 插入、删除和移动旅行日；
- App 重启后数据与路线缓存恢复。

### 10.3 UI 测试

覆盖核心路径：

1. 新建无日期旅行；
2. 搜索并收藏地点；
3. 编辑备注和标签；
4. 同一地点重复加入同一天和不同日期；
5. 拖动排序和跨日移动；
6. 覆盖路段交通方式；
7. 查看单日和全程地图；
8. 将草案转换为有日期旅行。

### 10.4 真机验证

必须在 Android 真机验证：

- 高德地图显示和生命周期；
- POI 搜索；
- 步行、驾车、打车和公共交通的产品表现；
- 跨城市公共交通失败表现；
- 断网和恢复联网；
- 多个标记和多日路线的地图性能。

## 11. 一期验收标准

使用一个三天旅行完成以下验收：

- 收藏至少 10 个地点；
- 同一家酒店连续三天且每天可出现多次；
- 任意一天增删和排序后，仅受影响路段进入重算；
- 自驾旅行的新路段推荐驾车；
- 非自驾旅行按不超过 1 公里步行、超过 1 公里打车推荐；
- 用户可以覆盖任意路段的交通方式；
- 单日地图按顺序展示真实路线；
- 全程地图以不同颜色叠加三天路线；
- 杀死并重启 App 后，旅行、地点、编排和成功路线仍存在；
- 无网络时可以继续编辑已有地点，恢复网络后待计算路线自动完成。
