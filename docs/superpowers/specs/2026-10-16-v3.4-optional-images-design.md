## 1. 用户目标与范围

用户先要求城市识别时“把图片改为可选项，失败可以不用管”，随后明确“所有地方，图片都是可选的”。

因此不再限定为全局助手第一步：全局识别城市、创建后的攻略交接、已有旅行内导入、直接添加图片、重试和草稿恢复，都遵循同一规则：

> 图片是可选辅助。图片缺失、下载／解码／识别失败，不阻断其他有效素材和已成功结果；不要求用户修好或重试图片才能继续。

“可选”不是完全不读图，也不是把失败当作“图片里没有地点”。没有成功读取的内容不得生成城市、地点或证据。

- 不新增图片必选／可选开关或页面。
- 日期继续可空，城市不能识别时允许手动填写。
- 最终地点上限100、图片最多处理20张、行程最多30天保持。
- 自动攻略仍仅保留独立游览目的地；住宿、餐饮、内部设施、背景地名等排除规则不变，手动添加不受该筛选影响。
- 一次收藏写入成功结束整批，未选／失败素材随该批结束；写入失败才保留批次供幂等重试。
- 不涉及提交、推送、安装手机或发布授权。

## 2. 当前代码核对与升级原因

规格编写时本地 HEAD 为 `38a1c484`；Native 实施前已安全 rebase 到 `16e6bccdfc4346b64ce09828286239658236cdc8`，保留一次收藏结束整批功能 `2103ae25`。下列问题是修改前基线，不能把旧的“部分收藏继续该批”逻辑作为当前目标。

现有阻塞并非只有下载器：

1. `AssistantLinkDom`／`AssistantLinkDocument.validated` 要求图片数量完整，正文可用仍可能等到超时。
2. `DefaultAssistantLinkLoader` 任一图失败会撤回本轮全部已下载图片并抛错。
3. `ModelGuideDestinationInterpreter` 文字无城市后逐图处理，任一图片异常会中断识别。
4. `GuideBatchBody` 可以将正文和图片置于同一HTTP请求；整组因图片被拒绝时正文也一起失败。
5. `PlaceAssistantController` 对“不支持图片”的模型会在文字请求前阻断整批。
6. `GuideMaterialStore`／交接复制逐张强校验，单个图片文件失效会阻塞有效文字和结果恢复。
7. `hasIncompleteMaterials`／交接状态将图片失败视为整体未完成，UI引导重试。

这是共享素材、请求隔离和恢复语义的调整，按架构路径评审，不用局部 `catch` 冒充全链路修复。

## 3. 方案选择

| 方案 | 取舍 |
|---|---|
| 仅吞掉下载异常 | 最小改动，但DOM、模型整组拒绝、能力检查和恢复仍会阻断；不采用 |
| 保持图文同请求，整组失败后自动重发纯文字 | 成功时调用少，但正文依赖图片请求结束，自动补发增加不确定费用且可能重复处理；不作为默认路径 |
| **文字独立，图片有界、可跳过，统一保存每源真实状态** | 多一次独立文字提取，但不再因图片请求失败损失文字；采用 |

图片之间仍按已有真实字节预算合并，不退回固定逐张地点提取。图片请求保留同一正文／城市作为理解上下文，但不能再次产出文字来源的提取回执。成功证据再复用既有整理、高德匹配、手动收藏。

这一点明确取代此前“预算内正文＋全部图片必须一次提取”的调用数要求。正文与图片都成功时，通常为一次文字提取、若干预算内图片组提取、后续整理；不承诺固定两次请求。

## 4. 统一素材读取规则

### 4.1 原帖文字与图片分别判定

- 保留支持平台、HTTPS、跳转、原帖归属和登录／验证安全检查；不放开任意域名、私网地址或CDN。
- 原帖标题／正文可以独立成为可用文字，不再要求轮播总数已知、所有图片齐备或全部懒加载完成。
- 原帖结构与归属仍必须确认；不能把登录页、推荐区或分享套话当成原帖正文。
- 图文笔记正文为空但有已确认的原帖标题或原帖图片时，可以使用已有有效部分；两者都不可得则真实报告无可用素材，保留输入。
- 只取得标题时明确记录“正文未取得”，不能把标题包装成完整正文，也不能宣称攻略覆盖完整。
- 不新增平台，也不扩展视频笔记支持或提取视频帧。
- 稳定就绪判断以原帖身份和可用文字为依据，不让图片列表持续变化重置文字就绪状态。
- 预计图数未知、计数冲突、缺图、重复变体、单个非法图片URL只影响图片可用性；非法URL不得发请求。
- 链接超过20图时按原帖顺序最多尝试20张安全且不同的图片，其他图记录为未处理，不阻断文字，也不声称读完全部图片。原图序号和本批来源ID分别保留，不通过重排把图21冒充原帖图1。
- 手动选择仍保留最多20张与现有体积安全上限；拒绝新增超限图时保留原输入和已有有效图，不禁用有效文字发送。

### 4.2 下载、解码与图片预算

- 读取文字后即进入文字处理，不把全部图片下载作为前置条件。
- 下载／解码按张隔离；一张失败清理该张临时文件，保留其他成功图。不因图片异常回滚正文或所有图片。
- 图片下载最多2个并发；本次链接可选图片下载阶段总预算30秒，单请求不超过现有30秒。阶段超时只结束剩余图片，不变成正文失败。
- 保留单图、总字节、像素、解码、请求体和响应体安全预算。超限素材跳过，不能以“可选”为由绕过安全验证。
- 本轮自动处理至多尝试一次下载，不循环重试坏链接。
- 对链接图片的“未发现”“下载失败”“超时”“不安全”“超限”保留原因。只在有可信总数时显示具体漏图数量；总数未知不得猜“跳过0张”。

## 5. 模型与成功条件

### 5.1 全局创建

1. 用用户文字与已核验原帖文字请求城市识别；不先提取地点。
2. 文字识别到城市，结束城市识别，不为此步骤下载或发送辅助图片。
3. 文字未识别到城市时，才在可选图片预算内尝试可用图；某图失败继续其他图，不因一张失败撤销已确认的城市。
4. 图片辅助总阶段预算180秒；自己的超时按图片跳过处理。保留用户主动取消、输入代次校验及已发送内容无法撤回的事实。
5. 无有效城市进入既有手动填写／确认路径；不能把失败或超时解释为某个猜测城市。多城市不强套单城。
6. 日期仍独立使用用户意图解析；不能因为可选图片缺失强填日期。

第一步未下载图片不代表用户放弃后续地点提取。创建后第一次地点导入仍可尝试尚未处理的图片；第一步已经明确失败／跳过的图片不自动反复重试。

### 5.2 已有旅行、交接导入和直接图文输入

- 有文字时，文字提取目标与图片提取目标分属不同请求；文字任务不以图片准备成功为条件。
- 图片仍按现有体积预算成组；全应用模型提取最多2个在途不变。
- 图片阶段总预算180秒，包含排队、格式补救与图片模型请求；该阶段超时保留已完成来源，其余图片跳过。不得通过共享外层超时把已经成功的文字抹掉。
- 文字自身请求的既有超时、鉴权、协议与证据验证仍有效；图片可选不能掩盖文字或整理器的真实失败。
- 单图协议／证据错误只拒绝该源，成功来源继续；整图片组网络失败只影响该组，不自动换模型、改服务或整批重发。
- 已知模型不支持图片时跳过图片，仍允许文字请求；不修改用户的模型能力设置。不支持图片不再触发全文阻断。
- 有成功有效来源即可整理、匹配和手动收藏；图片失败本身不再决定“整个攻略导入失败”或要求重试。
- 沿用本轮来源终态后统一整理，不新增流式半响应查询；图片达到自己的预算即终止等待，以已成功来源继续。不能为了等图片不断延长预算，也不能把未完成来源伪装为成功。
- 失败图片不伪装成 `NO_PLACES`、空成功回执或完成覆盖；既有实体来源／父子分类／别名证据校验不放宽。
- 若所有有效来源都失败，或成功读取但没有独立景点，沿用真实空结果／补充输入提示；不展示“成功导入0个地点”。
- 全局鉴权失败仍作为服务配置问题处理，不把它包装成图片缺失，也不无意义地反复尝试。

## 6. 交接、持久化和恢复

### 6.1 不再用“已有缓存”推断“全图完整”

材料记录显式区分：

- 原始分享文字／URL、已读取的原帖文字；
- 稳定素材来源及原图序号；
- 尚未尝试、可用、已跳过的图片状态；
- 成功文件的摘要与位置，以及跳过原因；
- 原帖图片覆盖是否已知，而非只凭本地图片列表长度猜完整性。

城市阶段未尝试的图片，在旅行内首次领取时继续处理；已跳过图片不会因恢复或页面重开自动重新发送。成功下载图和成功模型证据可复用，不重复导入、计数或发送原链接。

### 6.2 恢复兼容与完整性边界

- Room保持schema13；材料文件如增加字段使用明确的新版本，并兼容读取旧version1，不将不认识的版本当空白批次。
- 旧材料中的已存图片视为曾准备成功；恢复时缺失／损坏的单图转为可选不可用，保留文字、其他图与既有已验证结果。
- 原材料记录本身的摘要不符、错误session、路径越界、非法JSON或超大日志仍是记录完整性错误，不能用“图片可选”吞掉。
- 已验证并持久化的提取证据不因原图片后来被清理而自动撤销；缺图不能重新生成来源摘要、伪造新票数或证明未读内容。
- 新记录原子写入，失败保留上一个有效文件；引用／覆盖锁、稳定来源ID、取消代次不变。
- 恢复不自动联网重试失败图片，不自动重建已删除旅行，不重复领取交接、创建或收藏。
- 收藏写入成功结束整批；不再要求等图片恢复。收藏写入失败保持原批次和幂等回执供重试。

## 7. UI最小调整

不新增页面或设置，只同步已有状态：

- 成功文字／素材存在时，不弹“图片不完整，无法导入”等阻断错误。
- 可在现有进度／素材区域轻提示“部分图片已跳过，已使用可用素材”；有可信数量时才显示张数。
- 已跳过图片不计入必须解决的未完成数量，不让“重试导入”成为进入结果的前置操作。
- 用户仍可主动重试失败图片，但无需重试也能标记、收藏和创建。手动重试仅触及选择的失败来源，保留已验证结果。
- 主动取消与跳过失败图片不同，取消不自动继续发送剩余请求。
- 图片全部失败且没有可用文字时，城市允许手动填写；地点页提示没有可识别素材，保留输入供补充，不出现伪成功。

## 8. 验收边界

规格确认同时确认以下测试边界；实现时逐个进行先失败、后通过验证，不提前以旧测试结果替代。

| 公开行为边界 | 必须验证 |
|---|---|
| 双平台读取器／加载器 | 正文可用而图片0张、缺张、计数未知／冲突、非法URL、超20、下载超时、解码失败均不阻断有效文字；原帖归属、登录页、恶意跳转仍拒绝 |
| 全局城市识别 | 文字有城市时0图片下载／模型请求；文字无城市、坏图后好图、全图失败进入手动、取消／输入变更不被晚结果覆盖 |
| 生产输入处理器／请求边界 | 实际文字请求不携带图片；图组失败／不支持图片不让文字一起失败；图片组体积预算、并发2、自己的超时与用户取消分开 |
| 整理／控制器 | 图片全失败而文字成功仍出结果；坏图不计为完整证据；仅图片全部失败显示真实空结果；分类、安全、100地点规则保持 |
| 材料存储／交接 | 缺一图仍能恢复文字与其他素材；损坏整个材料记录仍拒绝；城市阶段未尝试图首次导入尝试、已跳过不自动重试、原分享只交接一次 |
| 恢复／收藏 | version1与新版兼容、摘要/来源ID稳定、已验证结果保留、仅手动重试失败图、一次收藏结束整批且不复活 |
| UI | 无图片必填／强制重试提示，普通及320dp／2倍字体可操作，主动重试可选，取消行为真实 |

需要 Debug／Release JVM、相关设备回归、lint及构建验证；真实小红书／携程链接验证须区分“真实读取”与“真实模型质量”。本规格不授权额外付费模型测试，不把fixture或旧V2结果称作本轮真实质量通过。
