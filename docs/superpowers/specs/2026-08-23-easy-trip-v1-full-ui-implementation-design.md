# Easy Trip v1.0 全量 UI 与交互落地设计

## 1. 背景

上一轮实现按 `2026-08-23-easy-trip-v1-pencil-implementation-design.md` 的第一批范围，完成了设计主题、部分共享组件、旅行列表、创建状态机、工作台外壳，以及“创建 → 进入 → 返回 → 再次打开”的真实数据闭环。

本轮不是否定或推倒第一批，而是在其基础上继续完成 `design/easy-trip-v1.0.pen` 的全量落地，并修正第一批范围内仍存在的显著视觉偏差。

最终范围覆盖：

- 48 个编号产品画面；
- 7 条用户旅程；
- 6 组状态矩阵；
- `design/easy-trip-design-formula.md` 的全部产品、交互、状态与验收约束。

`design/easy-trip-v1.1.pen` 不属于本轮视觉基线。

## 2. 基线与冲突优先级

发生实现、文档和设计冲突时，按以下顺序处理：

1. `design/easy-trip-design-formula.md`；
2. `design/easy-trip-v1.0.pen`；
3. 最新产品规格文档；
4. 旧设计稿、旧 TODO 和现有代码行为。

已确认的冲突处理：

- 地点详情移除“加入行程”和“已安排到某天”等行程操作；
- 加入行程只能从地点池发起；
- 旅行设置移除“添加一天”；
- 新增旅行日只能从行程左侧天导航末尾“添加”进入；
- 旅行日不可拖动换序，不可单独修改某一天的日期；
- 其他同类冲突均以设计公式为准，并在验收记录中注明与 `.pen` 的差异。

## 3. 目标与非目标

### 3.1 目标

1. 完整实现 48 个编号画面表达的页面、弹层和状态。
2. 走通 7 条用户旅程，并覆盖 6 组状态矩阵。
3. 保留第一批已经正确建立的主题、组件、状态模型和真实数据闭环。
4. 将搜索、地点池、加入行程、单日与全程行程、设置、权限、异常和危险操作纳入同一视觉与交互体系。
5. 以真实 Room 数据、现有 Repository、Service 和高德地图能力驱动正式 UI。
6. 每个设计场景都具备可构造状态、自动化入口、真机路径和视觉对比记录。
7. 每个实施批次独立可运行、可验证；本批未通过门禁前不进入下一批。

### 3.2 非目标

- 不使用 `design/easy-trip-v1.1.pen`；
- 不修改 Room schema；
- 不引入新的依赖注入框架；
- 不重写 Repository、Service 或高德地图适配层；
- 不为每个编号画面建立独立路由；
- 不复刻 Android 系统状态栏、系统导航栏或系统权限弹窗；
- 不自行补造深色主题；
- 不为了匹配固定画布而破坏安全区、字体缩放和小屏可用性。

## 4. 总体架构与迁移策略

### 4.1 保留边界

保留：

- Room、DAO、Repository、Service 和领域模型；
- 高德地图 Compose/View 互操作和地图数据能力；
- Navigation Compose；
- ViewModel、`StateFlow`、`SavedStateHandle`；
- 手写 `AppContainer`；
- 第一批建立的 Easy Trip 主题和可复用组件中符合本规格的部分；
- 已有真实创建、收藏、加入、排序、路线和删除能力。

### 4.2 迁移方式

采用垂直用户闭环增量重构：

- 每批同时完成该闭环的 UI、状态、导航、业务连接和测试；
- 一个闭环通过门禁后，删除该范围内被替代的旧 UI；
- 不长期维护两套视觉和行为重复的实现；
- 过渡期间保留未轮到批次的旧页面可用性；
- 不以静态假数据页面替代正式链路。

### 4.3 48 画面的工程表达

48 个编号画面是验收场景，不等于 48 条路由。每个场景记录：

```text
frameId
→ UiState fixture
→ Compose 测试入口
→ 真机操作路径
→ Pencil 截图
→ 运行截图
→ 差异与结论
```

独立页面建立路由；抽屉、弹层、权限说明、加载、失败和反馈由页面状态驱动。

## 5. 导航与页面边界

### 5.1 独立路由

```text
trips
trips/create
trips/{tripId}/workspace
trips/{tripId}/search
trips/{tripId}/settings
```

### 5.2 返回行为

- 创建页返回旅行列表；未提交内容通过明确离开行为处理，不静默提交；
- 搜索页返回工作台地点池，不自动进入行程；
- 工作台存在覆盖层时，系统返回优先关闭最上层覆盖层；
- 无覆盖层时，工作台返回旅行列表；
- 返回旅行列表后继续由 Room Flow 展示最新内容；
- 重新进入工作台时恢复当前 Tab、天范围和抽屉档位。

### 5.3 Route 与 Content

每个独立页面分为两层：

```text
Route
├── 获取 ViewModel
├── 收集 StateFlow
├── 消费一次性 Effect
├── 连接导航、生命周期和系统权限
└── 调用 Content

Content
├── 接收不可变 UiState
├── 发送 UiAction
├── 不访问 Repository 或 Room
├── 不持有 NavController
└── 可由测试和 Preview 构造
```

主要边界：

- `TripListRoute / TripListContent`
- `CreateTripRoute / CreateTripContent`
- `TripWorkspaceRoute / TripWorkspaceContent`
- `PlaceSearchRoute / PlaceSearchContent`
- `TripSettingsRoute / TripSettingsContent`

## 6. 工作台状态与所有权

### 6.1 协调状态

```text
WorkspaceUiState
├── trip
├── activeTab: PLACE_POOL | ITINERARY
├── sheetValue: COLLAPSED | HALF | EXPANDED
├── mapState
├── placePoolState
├── itineraryState
├── selectedDayScope
└── overlay
```

同一时间只允许一个主要覆盖层：

```text
None
PlaceDetail(placeId)
SelectPlacesForDay(dayId)
SelectTargetDay(placeIds)
AddTripDay
EditItineraryItem(itemId)
EditRouteLeg(legId)
LayerMenu
Confirmation(...)
PermissionExplanation(...)
Feedback(...)
```

### 6.2 状态所有权

- `TripWorkspaceViewModel`：旅行、一级 Tab、抽屉、地图范围和覆盖层协调；
- `PlacePoolViewModel`：收藏地点、选择、备注和标签；
- `ItineraryViewModel`：天范围、排序、行程项和路段；
- `TripSettingsViewModel`：名称、日期范围、删除影响；
- `PlaceSearchViewModel`：搜索词、请求状态和收藏切换。

工作台 Route 组合状态后传给 Content。Content 不直接订阅多个 Flow。

### 6.3 持久状态

Room 保存：

- Trip、TripDay、SavedPlace、ItineraryItem、RouteLeg；
- 标签、备注和地图偏好。

`SavedStateHandle` 保存：

- 当前工作台 Tab；
- 当前天范围；
- 抽屉档位；
- 搜索词；
- 多选地点 ID；
- 未提交表单内容；
- 当前编辑目标 ID。

只在内存中保存：

- Snackbar；
- 动画进度；
- 当前按压与拖动状态；
- 一次性导航和权限请求 Effect。

## 8. 系统 UI 与响应式规则

### 8.1 系统 UI

系统状态栏和系统导航栏由 Android 负责：

- 不绘制时间、信号、电量、手势条或三键导航；
- 不固定预留 `.pen` 中的 `62dp Status Bar`；
- 使用 `WindowInsets.statusBars`、`navigationBars`、`ime` 和 `safeDrawing`；
- 根据页面背景设置状态栏图标明暗；
- 截图对比忽略不同设备和系统版本导致的系统栏差异。

### 8.2 响应式

- `390 × 844dp` 仅为视觉对比基准；
- 页面不固定高度；
- 横向尺寸服从设备约束；
- 列表使用 Lazy 容器；
- 表单可滚动，并处理键盘 Insets；
- 小屏和字体放大时优先保证内容可读、操作可达；
- 内容增加时不压缩字号、行高、地点行或 RouteLeg；
- 必要时通过滚动、抽屉展开或裁切提示处理溢出。

## 9. 工作台视觉结构

```text
Android 系统状态栏（系统负责）
└── 应用工作区
    ├── 地图背景
    ├── 顶部旅行信息
    ├── 不透明白色搜索框
    ├── 地图控制按钮
    ├── 贴合内容的地图图例
    └── 底部抽屉
        ├── 地点池 / 行程普通 Tab
        └── 当前业务内容
Android 系统导航栏（系统负责）
```

规则：

- 地图持续提供空间上下文；
- 搜索框不得缩成图标按钮；
- 地图控件不得与标题、搜索和菜单重叠；
- 图例宽度贴合内容；
- 一级 Tab 使用透明背景、主色加粗文字和 `3dp` 指示线；
- 一级 Tab 不使用胶囊背景；
- 抽屉支持收起、半屏和全屏三档；
- 抽屉内容独立滚动。

## 11. 数据一致性与失败恢复

### 11.1 本地优先

```text
页面可用性 = 本地 Room 数据能力 + 可选网络增强
```

- 本地旅行、地点池和行程不依赖网络显示；
- 网络失败不清空本地内容；
- 地图失败不阻断业务操作；
- 路线失败只影响对应 RouteLeg；
- 联网恢复后只补算待处理路段。

### 11.2 收藏

```text
搜索结果 → 写入 SavedPlace → Room Flow 更新 → UI 显示已收藏
```

收藏后不自动返回，不直接创建 ItineraryItem。

### 11.3 加入行程

```text
地点池多选 → 选择 TripDay → 创建 ItineraryItem
→ 追加到当天末尾 → 更新受影响 RouteLeg
```

- 同一 SavedPlace 可对应多个 ItineraryItem；
- 不按 `placeId` 去重；
- 目标日失效时停止提交并要求重新选择；
- 不静默改投其他日期。

### 11.4 排序与编辑

- 拖动只改变同一天内的顺序；
- 只重建受影响的相邻 RouteLeg；
- 修改时间、停留时长或交通方式不改变地点身份；
- 跨旅行日不生成 RouteLeg。

### 11.5 部分成功

收藏成功、加入失败时：

- SavedPlace 不回滚；
- 明确显示地点仍在地点池；
- 提供“重试加入第 N 天”和“仅保留收藏”。

保存失败时：

- 保留当前编辑内容；
- 显示“修改尚未保存”；
- 提供“继续编辑”和“重新保存”。

撤销本次加入时：

- 只删除本次创建的 ItineraryItem；
- 删除或重建受影响 RouteLeg；
- 不删除 SavedPlace；
- 不影响之前已存在的相同行程项。

## 12. 危险操作与权限

### 12.1 危险操作

以下操作必须二次确认：

- 删除旅行；
- 删除旅行日；
- 删除行程项；
- 缩短日期范围导致旅行日删除。

确认层必须说明：

- 被影响实体；
- 将删除的数据；
- 将保留的数据；
- 是否可撤销；
- 删除后的编号或路线变化。

### 12.2 权限

地图服务授权与定位权限分离：

- 地图服务未授权时，地图区域显示用途说明，地点池和行程保持可用；
- 定位权限只在点击定位按钮后请求；
- 先显示应用内用途说明，再调用系统权限弹窗；
- 永久拒绝后提供系统设置入口；
- Compose 不模拟系统权限弹窗。

## 13. 测试与验收

### 13.1 JVM

覆盖：

- 页面状态映射；
- 表单校验和提交防重；
- 多选地点和目标日失效；
- 同地点重复加入；
- 追加到当天末尾；
- 排序后的邻接 RouteLeg；
- 日期范围缩短影响计算；
- 部分成功和保存失败；
