## 三、建议下一阶段优先级

### P0：产品与视觉语义裁决

预计 0.5 天。

先确认：

1. “更多”入口最终语义。
2. 地点池行操作样式。
3. 空态插画资源等级。
4. RouteLeg 与行程卡片的信息密度目标。

这些决定会影响多个页面，先裁决可减少返工。

### P1：行程内容族

预计 2–3 天。

范围：

- 单日行程。
- 全程行程。
- RouteLeg。
- 行程项编辑、时间、移动和删除。
- 等待联网、失败、重试和局部成功状态。

工作台壳层已经稳定，下一步应优先收敛信息密度最高的内容区域。

### P2：搜索、地点池与地点详情族

预计 1.5–2.5 天。

范围：

- 搜索初始、加载、结果、无结果和失败。
- 地点池普通、空态和搜索返回状态。
- 地点详情、备注、标签、收藏与取消收藏确认。
- 搜索入口多实现的后续清理。

### P3：我的旅行、创建与共享空态

预计 1.5–2 天。

范围：

- 我的旅行列表、卡片和空态。
- 创建旅行表单和校验。
- 共享空态、提示和插画。
- 当前模型缺少的统计数据只做讨论，不伪造。

### P4：设置、日期与权限族

预计 1.5–2.5 天。

前置条件：先裁决“更多”入口。

范围：

- 旅行设置。
- 日期范围修改和影响确认。
- 删除旅行日、旅行和行程项确认。
- 地图授权、定位权限与前往系统设置。

### 独立技术批：响应式连续性

预计 1–1.5 天，可与页面视觉工作并行，但不混入页面批次。

范围：

- 修复 395/396dp expanded anchor 跳变。
- 补充连续性和锚点有序测试。
- 再评估横屏、分屏和 2×字体的最小安全边界。

## 四、三种推进策略

### A. 按页面族垂直切片

每次完成一个页面族的设计、实现、自动化和代表性验收。

优点：持续产生可见结果，范围容易控制。  
缺点：共享组件或语义决策过晚时可能返工。

### B. 风险优先

先完成语义裁决、响应式和共享组件，再处理页面。

优点：降低后续返工。  
缺点：前期用户可见变化较少。

### C. 按 47 场景逐屏修复

不推荐。容易重新进入逐屏补丁、截图膨胀和共享组件反复修改。

### 推荐：A + B 混合

1. 先用 0.5 天完成关键语义裁决。
2. 之后按页面族垂直切片。
3. 395/396dp 响应式问题作为独立技术批并行处理。
4. 47 场景只作为行为契约和回归索引，不作为逐屏实施顺序。

## 五、统一 Mate 60 Pro 真机验收

不建议每个小改都占用真机。建议：

1. 每个页面族先通过 JVM、focused Compose、lint 和 APK 构建。
2. 页面族候选版本冻结后，统一执行一次 Mate 60 Pro 正常竖屏验收。
3. 最终再做一次跨页面族总验收。

工作台代表状态至少包括：

- 半屏地点池。
- 半屏行程。
- 展开行程。
- 搜索返回。
- 长旅行名。
- 地图失败或授权未完成。

后续页面族各追加 1–2 条代表路径。真机结果单列，AVD 不替代真机。

## 六、模拟器稳定性与 UI 开发解耦

- connected tests 全局互斥、串行执行。
- 先跑单类，再跑页面族套件，减少频繁全量 connected。
- 同一基础设施失败最多重试一次。
- signal 9、长时间无进展或设备丢失标记为 `INFRA-BLOCKED`，不得直接归因于产品代码。
- UI 开发可继续 JVM、编译、lint 和静态审查；设备恢复作为独立 0.5–1 天技术 track。
- 每次设备任务记录测试类、当前测试编号、进程树、logcat、guest/宿主内存和 UTP 状态。
- 诊断参考：[Easy Trip Android 测试基础设施卡死诊断](https://bytedance.my.larkoffice.com/docx/RViXdHClzoa2GcxYWuYmx56OyEf)。
