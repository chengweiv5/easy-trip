## 实际改动

- 三阶段固定提示词：正文、原图、跨素材整理均以整篇攻略的独立游览目的地为目标。全部住宿（含推荐）、餐饮食品、内部舞台/拍照布景/普通出入口/停车场、交通节点、背景和方位参考排除。独立介绍的历史建筑、博物馆不因处于更大景区内部机械删除。
- `GuidePlaceClassification`：模型返回用途、层级、独立游览判断、原文证据；客户端执行分类，未知或证据不足进入现有待核对状态。分类只用于攻略，不改变手动添加。
- 整理阶段同时检查保留与删除依据。无分类、无原文依据或 UNKNOWN 的删除不能静默丢点，而是保留为待核对；正常成功项仍可高德查询/手动收藏。有效住宿/餐饮/内部细节分类不加例外。
- 将候选在正文中出现的原始行逐项传给整理步骤，即使正文提取失败，也不丢失餐饮地址语境；不使用城市/地点黑名单。包含关系不作为别名。拼接多个中文地点的名称只待核对，不直接查询；不自动拆出臆测地点。
- 来源兼容：仅忽略排版空白；正文名称与紧邻说明可从原文恢复连续摘录；地图名称标签和介绍分栏时保留两者，不用模型的无引号推断当名称证据。城市前缀扩写仅可回退至图中确实摘录的短名并标待核对，不能猜全名。
- 完整合法工具参数对象后只有 1–2 个多余右花括号可本地容错；截断、多对象、额外文字、非预期工具仍拒绝。格式补救仍最多一次，网络失败不增加自动重试。
- 攻略结构化输出额度由 8192 提至 32768 tokens，避免新增分类/摘录使 100 个地点更容易截断；手动输入仍 8192。攻略采样温度设 0，降低波动但不宣称确定性。20图、100地点、30天、版本 3.4.0/build27/schema13 不变。
- UI 仅整理进度与通用待核对文案；Pencil 只更新 C11/C12 context，没有新增页面。
