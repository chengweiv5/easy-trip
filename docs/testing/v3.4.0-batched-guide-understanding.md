## 实现

1. 旅行内攻略导入使用 `GuideBatchModels/Protocol/Body/Files/Scheduler/Parser`，正文和图片预算内一次合并提取，再走原纯文字语义整理一次。无候选不调用整理；补救和手动重试另计，不承诺任意场景恒为两次。
2. 完整 UTF-8 HTTP body（含 Base64、JSON 和补救开销）按字节组包，不按固定图数。精确官方 HTTPS 主机／端口／Flash 模型采用16MiB、32768输出tokens；兼容服务保守使用6MiB、8192。普通入口限制不变。
3. 私有图片副本逐张准备；流式 Base64 和请求文件。全应用共享最多两个攻略提取请求，无700ms延迟；高德节流仍为700ms／最多两个在途。组数多不意味着增加语义整理次数。
4. 多源回执保留本地来源身份；第二组先返回仍按原来源顺序归并。每源独立失败、缓存成功、只重试失败源。仅可修复格式最多一次补救；网络、鉴权、限流、截断、事实证据错误不自动重发，不放松来源校验。
5. AppContainer及两处真实Factory已接线；普通文字、单图入口与全局城市识别不改调度。资料和模型字段不能执行工具、生成可信本地路径或触发收藏。
6. 部分收藏后恢复保留原攻略、成功来源、用户手改和已有POI；失败重试增量合并、不重复收藏。恢复记录保持version1和1MiB上限，写失败保护旧快照并避免错误自触发循环。
7. 进度沿用现有界面，正文／多图可同时处于理解中；分组错误不错误归咎于某张图。没有恢复此前移除的提示卡。
