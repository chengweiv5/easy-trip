# v3.4 助手一次收藏结束整个批次

日期：2026-10-16。工作树 d7c9，分支 `codex/fix-assistant-single-save-round`，基线 `b6b53909bde25ce8aaa6be2b38c5188c970fecb7`。

## 用户明确的规则

“失败的我就不会管了，收藏按钮我只点一次就要结束这一批次。”

- 收藏按钮点击一次、所选地点持久化成功后，结束整个批次。
- 清空本批输入、图片、所有候选（包括未选、识别失败、待整理、查询失败项）、选择、进度、焦点及助手地图候选，回到可编辑空输入。
- 保留当前旅行、城市与所有已收藏地点。成功提示保留，不新增确认页或继续按钮。
- 只有本次收藏写入失败才保留本批与选择，重试复用同一 operation ID；重复点击不得重复提交。
- 收藏前的失败素材单独重试、未收藏草稿恢复仍可用。收藏成功后不再等待失败项、不自动补查，不恢复已结束批次。

本规则取代 2026-10-15 部分成功方案中“部分收藏不结束攻略”的例外；`v3.4.0-partial-success.md`、证据恢复文档及旧设计 C39 中相反描述仅为历史，不可继续作为当前验收标准。本次不修改已确认的正圆标记外观。

## 根因与责任边界

`633703a6` 于 2026-10-15 加入 `saveSelected()` 的 `hasIncompleteMaterials` 提前返回：事务成功后只将行改为已收藏，而不调用结束批次清理。`hasIncompleteMaterials` 包含失败素材和 `normalizationPending`；`2d083b6e` 的证据 V2 继续使用这个分支。

`8e742416` 的地图标记提交只修改标记渲染、列表徽标和样式，不直接修改保存逻辑，但交付包包含上述例外。上一轮验收沿用“部分收藏保留”的断言，未核对它与原来“一次成功收藏结束本轮”的要求是否冲突，不能拿测试通过证明需求正确。

本轮先在仓库外注入测试，普通收藏 7 项通过，失败素材／待整理证据两个“成功后必须清空”的断言失败；隔离复制控制器仅移除提前返回，两项转绿。此为固定服务的生产控制器复现，不冒称抓取了用户手机当时的批次或日志。

## 实现

1. 去掉未完成素材的保存成功提前返回，统一进入原有批次结束路径。
2. 首页交接与直接粘贴的证据批次统一使用 `guide:<batch>:<digest>` 收藏回执。首页交接沿用 Room 事务内完成状态；直接粘贴用同一批次标识查询持久回执，不改 schema。
3. 恢复本地草稿前先检查完成回执。即使进程在提交成功、清理草稿前中断，也不恢复旧批次。
4. 回执恢复移到草稿恢复／清理及图片门禁释放之后。首轮设备验证暴露此前并发读取可能漏掉成功回执，本轮修复后重新构建验证。
5. 调整旧“收藏后继续失败重试”的测试为“收藏前可恢复／可重试，收藏后结束”；保留别名、手动修改、来源与幂等边界。
