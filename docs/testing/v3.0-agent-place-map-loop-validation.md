## 3. Phase 2：DeepSeek 工具调用接真实地点查询

输入：「请把杭州的雷峰塔标记在地图上供我确认，先不要收藏。」

1. 官方配置的 `deepseek-flash` 返回有效 `search_places`，query=雷峰塔、city=杭州。
2. 宿主 Python transport 将校验后的工具参数写入隔离 App 文件并回读一致。
3. Android 探针读取真实工具参数调用真实 SDK，不把硬编码参数冒充模型输出。
4. 20 个真实结果及本次随机核验码返回模型；第二轮回显核验码并说明尚未收藏。
5. 再经过测试用户点击、保存去重、清除搜索层与独立进程重启，全部通过。

该连接方式是 **宿主 transport → 临时 Android dispatcher → 现有业务**，不等于 Kotlin AgentRuntime 已集成。模型最终文字先于 UI 预览阶段返回，因此其文字“已标记”不是渲染证据；渲染由后续 native marker 和截图独立证明。

恰好 **2 次新模型请求、2/2 HTTP 200、0 重试/重定向**；thinking disabled、非流式、max_tokens 512。usage 合计 **2,743 tokens**。两个请求分别约 0.783 / 1.062 秒，仅两次样本，不是稳定耗时或费用承诺。预算已用完，本轮没有额外调用。
