# 行程内容族 UI 冲突与裁决

日期：2026-08-26

## 已裁决

### PENDING 与 CALCULATING 的 UI 映射

- 冲突：领域模型有 PENDING、CALCULATING 两态，批准设计只定义一个 Calculating UI 状态。
- 裁决：两者均显示“正在计算路线”，保留领域状态，不改数据层。
- 代价：排队等待和活跃计算在视觉上不可区分。

### 新增旅行日双入口

- 冲突：日期 rail 与无旅行日空态均提供新增旅行日入口。
- 裁决：保留两个入口，统一派发同一个 `onAddDay` action，不创建第二条业务流程。
- 代价：入口可能在最终真机体验中显得重复。

### RouteLeg 模式编辑范围

- 冲突：旧实现允许更多状态进入交通方式编辑，批准设计限定 Ready 状态可编辑。
- 裁决：仅 Ready RouteLeg 可进入模式编辑；Calculating、WaitingForNetwork、Failed 不开放该入口。
- 代价：不再支持离线或计算前修改交通方式的旧快捷路径。

## 待统一真机验收

状态：DEFERRED。

### 120dp 拖动步长

- 规格要求拖动阈值从原始 px 改为 dp 转 px，当前实现采用 120dp。
- 高密度设备上的物理拖动距离可能偏长，需统一真机批次评估手感。
- 在真机裁决前不回退为原始 px，也不自行改变阈值。

## 设计稿与生产语义

- 当前未发现需要阻断候选的新增冲突。
- Pencil 视觉稿不覆盖业务状态机；生产继续保留确认后变更、失败保留草稿、单路段重试和全程只读语义。
- PENDING/CALCULATING 的视觉合并属于明确裁决，不代表领域状态合并。
