## 上一轮范围与实现

- 仅攻略自动提取：正文、图片、最后整理统一回答“整篇攻略去哪些独立景点”，不是“景点里怎么玩”。固定模板不含本次城市或具体景点黑名单。
- 剔除内部舞台、演出位置、打卡墙、普通出入口、停车与交通节点；保留真正作为独立游览目标介绍的建筑、纪念馆等，不能仅因在大景区内就删掉。
- 餐饮地点及食品继续排除；餐饮标签里的街道／地址不能截取成独立目的地。明确夜游街区可保留。具体住宿仍为明确例外，不能被“只提取景点”误删。
- 客户端不再将模型已剔除的 `AUTHOR_MARK`／`RECOMMENDED` 小地点自动加回；父子混入一个别名组时拒绝冲突，不强行拆回子地点，不把子地点证据合给父地点。
- 图片仍只接收本图与城市，不加入整篇正文冒充图内证据；跨图与正文由最终整理判断。
- 未修改手动添加、POI匹配、部分成功与收藏控制器、数据库、版本或Pencil；保持100地点／20图／30天、400候选、schema13前向修复边界。

修改入口：

- `AssistantPlaceNormalizer.kt`：共享层级规则、最终整理、停止强制恢复。
- `ImagePlaceParser.kt`：图片独立目标与可核查用途证据。
- `AssistantAttractionLevelTest.kt`、既有normalizer测试：10项新增回归及原保护规则更新。
- `AssistantAttractionLevelLiveTest.kt`：显式opt-in生产读取器／解析／整理诊断；原`AssistantLinkLiveModelTest`更新旧入口强制保留假设。

## 真实模型：不能只挑通过结果

使用专用配置中的 **DeepSeek `deepseek-flash`**，在独占 `emulator-5600` 中调用生产 `DefaultAssistantLinkLoader`、正文／图片parser、`AssistantInputProcessor` 和 `ModelPlaceNormalizer`。不是Codex代为编造地点；没有真实高德调用、旅行库写入或真实收藏。

样例为用户既有徐州小红书10图、青州小红书6图、青州携程6图。每次读取真实公开内容，未登录平台。单次诊断最多28请求；只有显式传入`liveSourceRetryRounds`才调用既有失败素材接口重试最多2轮，产品没有新增网络自动重试。HTTP成功不等同于语义或来源校验成功。

### 迭代中真实观察

- 有版本得到徐州18项、青州小红书20／23项、携程19项等通过结果，但也发生汉文化景区漏提、餐饮地址街名误留、住宿漏提、范公亭简称重复。每次均补规则／断言后重新验证，没有删除反向断言让结果变绿。
- 最终明确住宿例外后，住宿恢复，但两个反向断言再次失败。因此先前进度中的“通过”只指当时单次样例，不能作为当前整体质量结论。
- 一次模型把古城与普通南门放入同组，客户端拒绝为 `INVALID_GROUPS`；没有改成自动合并或自动恢复。后续独立复测通过，但这仍说明可能需要用户重试整理。
- 全部可回读诊断共 **273次请求：207次HTTP200、66次HTTP503**。另有一次携程模拟器WebView原生 `Chrome_IOThread`／`partition_alloc` 崩溃，没有落盘完整请求数，未纳入总数。不能把它称为已证明的产品或平台根因。
- 无内部舞台等结果的改善是真实观察；“任意URL均稳定不误提、不漏提”未被证明。
