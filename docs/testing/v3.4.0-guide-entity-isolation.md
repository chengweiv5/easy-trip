## 2. 实际修复

### 单个出现项隔离

`GuideEntityProtocol.kt` 在强制分类的 V2 路径中，按原始 `[e, mentionIndex]` 单独验证每个出现项。某项的原文字面、父级或城市引用错误时，只把该项所在证据记为待整理，不中断同段后续合法地点，也不压缩索引。

重复/缺失的证据回执、整段括号结构不满足协议等仍是证据级错误。旧的不要求分类路径保留原行为。

### 别名组隔离

分组引用到**已经定位为错误的原始出现项**时，隔离该引用，再对保留下来的成员执行原有分组校验。未知索引不按已知坏项处理，仍拒绝；城市、角色、父子、方向、引用、冻结结果及互斥分组规则均保留。

这不是“把所有校验放开”，也不接受虚构的父名称，不自动生成替代地点。

### 固定 prompt 修正

`GuideEntityRequest.kt`：

- 删除残留的“已识别住宿保留”，统一排除推荐住宿。
- 明确主体景点与普通入口/出口分开判断；已有独立游览证据且主体名称在本条原文中连续出现时，另提取主体，不连带删除。
- 不用删除后缀、拼接、补字或跨证据补全来制造父景点；普通门不得与主体合并为别名。
- 已安排游览的路线起点、终点不因箭头/步行/公交标记就判为交通点；仅抵离、换乘、集合仍排除。
- 不加入具体旅行或城市名称。

主体保留属于 prompt 行为修正，**不是客户端自动从已排除入口补出父景点**；其真实模型执行效果仍待验证。
