## 范围与根因

- 当前954e工作树，功能分支`codex/v2.2.0-empty-trip-city-fix`，基线`2b45968430fd66391a449f53d848f9eebe9e6c19`；修改前获取origin/main，待合并PR为空。
- 原导航仅在创建成功时设置`locate-new-trip-city=true`，普通旅行列表入口不设置该标记，因此已有空旅行完全没有发起城市定位。旧导航测试还明确断言重新打开不定位，验收范围漏掉用户实际路径。

- 去掉创建入口专属标记，所有工作区入口在地图授权有效后统一调用`locateEmptyTripCity`；等待真实收藏快照就绪后，只有无收藏的旅行发起查询。
- 保留旅行名称首城市识别、12秒超时、已有收藏优先、迟到结果不可覆盖手势/搜索/新收藏等保护；同一次进入仅尝试一次，退出列表再进入可重新定位。不新增收藏，不改变地点池编辑。
- 将初始化尝试/手动抑制状态限定在当前ViewModel，避免旧SavedState中的一次性标记使重建后的空工作区不再发起请求。对此新增单元回归，先观察失败再修复；不把这一单元验证宣称为完整进程死亡恢复验收。

本次是已确认逻辑规则的修复，不修改页面布局、设计源、版本号或数据库结构。v2.2设计及此前开发记录中的“新建首次进入”描述属于原阶段范围，本文件记录用户本次明确的更正规则。
