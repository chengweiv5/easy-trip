## M1：旅行列表与创建旅行

### 准备

- 保留现有“登封”旅行。
- 新建专用旅行时使用名称 `手验-M1`。
- 建议日期使用跨月 3 天范围，例如 `2026-09-30` 至 `2026-10-02`。

### 操作步骤

#### M1-1 冷启动与旅行列表

1. 从系统最近任务划掉应用后重新打开，或正常强制停止后冷启动。
2. 检查页面标题、主旅行卡片、更多菜单和右下创建入口。
3. 核对主卡的旅行名、日期范围、天晚数、地点数、旅行日数、准备度百分比和进度条。
4. 点击主卡更多菜单，再点外部或系统 Back 关闭。
5. 点击主卡主体，确认能进入正确工作台；返回列表。

观察点：

- 主卡信息与真实旅行数据一致。
- 创建入口固定可达，不遮挡列表。
- 主卡主体和更多菜单点击语义不冲突。
- 无严重裁切或横向溢出。

建议截图：列表初始态、主卡更多菜单。

#### M1-2 创建页初始状态

1. 点击右下“创建旅行”。
2. 检查标题、步骤提示、旅行名称、日期入口、出行方式和说明文案。
3. 上下滚动，确认所有字段及底部操作可达。

观察点：

- 页面初始字段为空。
- “灵活 / 自驾”完整可见。
- 按钮文字在按钮中居中。
- 键盘未弹出时无严重裁切。

建议截图：创建页初始态、底部创建按钮。

#### M1-3 空表单校验

1. 保持名称和日期为空。
2. 尝试提交创建。
3. 检查名称和日期错误提示。

观察点：

- 两类错误提示明确且靠近对应字段。
- 已有输入不会被清空。
- 错误提示不遮挡字段或提交操作。
- 不创建空旅行，不发生导航。

建议截图：完整错误态。

#### M1-4 名称与键盘

1. 输入一个较长旅行名称，检查换行或截断。
2. 恢复名称为 `手验-M1`。
3. 键盘打开时向下滚动，检查日期入口和提交按钮。
4. 按一次系统 Back。

观察点：

- Back 优先关闭键盘，不退出页面。
- 名称草稿保留。
- 输入框和底部操作不被键盘永久遮挡。

#### M1-5 日期取消语义

1. 打开日期范围弹窗。
2. 选择一个临时范围。
3. 点击“取消”，确认创建页日期仍未选择。
4. 再次打开，选择临时范围后按系统 Back，确认仍未提交。
5. 再次打开，选择临时范围后点击 scrim，确认仍未提交。

观察点：

- 弹窗顶部不出现暗示可拖动收起的横线。
- 上月/下月和底部按钮内容居中。
- 今天有独立视觉强调和无障碍语义。
- 取消、Back、scrim 只丢弃本地日期草稿。

建议截图：日期弹窗初始态、临时选择态。

#### M1-6 跨月日期范围

1. 选择跨月 3 天范围，例如 `2026-09-30` 至 `2026-10-02`。
2. 检查开始、范围内、结束三个状态。
3. 点击确认。

观察点：

- 摘要显示完整范围及 `3天2晚`。
- 起止日期之间没有穿过数字的横线。
- 范围通过单元格背景和起止强调表达。
- 今天若与范围重叠，仍能识别“今天”。

建议截图：跨月范围选中态、确认后的创建页。

6. 冷启动应用，确认旅行仍存在且没有恢复键盘、弹窗或提交中状态。

观察点：

- 不重复创建。

- 三天仅一天有安排时显示约 33%，不是 100%。
- 所有日期有安排时才显示 100%。

   - 自动化：25% 像素回归先验证旧 Material 组件有 2 段橙色，再验证第一轮实现内部交界存在主卡背景像素；自绘实现 GREEN。完整 `TripListContentTest` 20/20、full JVM、assembleDebug、assembleDebugAndroidTest、lint、diff-check 通过。

4. **简化旅行日行尾操作。**
   - 删除右侧三个竖点表示的更多菜单。
   - 每个旅行日只保留一个垃圾桶删除按钮，不再通过二级菜单重复提供删除。
   - 保留删除确认、写入锁和影响统计逻辑。
5. **删除旅行日左侧三条横线拖动把手。**
   - 当前已定日期旅行不能移动，该图标会错误暗示可拖动排序。
   - 删除图标及对应拖动语义；不改变旅行日编号、日期和删除入口。
6. **修正旅行日列表连续卡片圆角。**
   - 第一天：仅顶部两个角为圆角，底部两个角为直角。
   - 最后一天：仅底部两个角为圆角，顶部两个角为直角。
   - 中间旅行日：四角均为直角。
   - 只有单个旅行日时四角均为圆角。
   - 相邻旅行日之间保持连续列表视觉，不出现独立圆角卡片拼接的断裂感。
7. **阻断：修改旅行日期后，旅行列表主卡没有重新选择最近的旅行。**
   - 复现：把当前主卡旅行的日期调整到比其他旅行更晚，返回“我的旅行”。
   - 实际：原旅行仍停留在主卡，日期更早、离当前时间更近的其他旅行没有成为主卡。
   - 期望：列表应根据最新 Room 数据重新排序，主卡始终显示最近的旅行；日期修改后必须自动重新计算，而不是保留旧 primary 身份或旧顺序。
   - 后续修复需明确并测试排序口径：优先最近的未结束已定日期旅行；同日使用稳定次序；已结束和日期待定旅行按既定产品规则排在后面。返回列表、Room Flow 回流和 cold start 的结果必须一致。

### 已发现问题

1. **简化单日行程顶部的添加地点入口。**
   - 选中某一天后，删除顶部可左右滑动的“添加 XX 地点”快捷按钮列表。
   - 删除独立的“从地点池添加”文字按钮。
   - 仅在“第 N 天 · M 站”标题右侧保留一个 `＋` 按钮，语义为“从地点池添加”。
   - `＋` 按钮点击后继续复用现有固定旅行日的地点池多选流程，不创建新的 route 或平行状态。
   - 按钮应至少满足 48dp 点击区域，与标题垂直居中；长标题、窄宽和字体缩放时不得挤出屏幕。
   - 空旅行日也使用同一标题右侧 `＋` 入口，不在正文重复显示第二个添加按钮。
2. **路段编辑改为整块路段信息可点击。**
   - 删除路段信息右侧独立的“编辑路段”按钮。
   - 成功路段的整块信息区域作为单一点击目标，点击后进入既有交通路段编辑界面。
   - 增加明确但克制的可点击视觉效果，例如整体 surface、按压反馈或右侧轻量指示图标；不得依赖文字按钮提示。
   - 保留起终点、交通方式、状态、距离和预计耗时，布局获得原按钮占用的宽度，减少窄屏换行。
   - 点击区域至少 48dp，并提供“编辑从 A 到 B 的路段”等无障碍语义。
   - Waiting/Calculating 路段不可编辑；Failed 路段继续保留唯一重试动作，不能因整块点击产生编辑与重试冲突。
3. **重做单日行程地点拖动排序反馈。**
   - 长按拖动把手后，被拖地点卡片应跟随手指实时上下移动，而不是仅在跨过固定阈值后跳变顺序。
   - 其他地点卡片应在目标位置变化时平滑让位，提供连续位移动画；路线段预览随临时顺序同步更新，不应闪烁或叠在地点卡片上。
   - 被拖卡片需有清晰拖动态，例如轻微抬升、阴影或背景强调；松手后平滑落位并只提交一次最终顺序。
   - 拖动取消时恢复原顺序；拖到列表上下边缘时支持自动滚动，以便长行程跨屏排序。
   - 拖动过程中不得触发行程项菜单、整行编辑或地图手势；无障碍自定义“上移/下移”动作继续保留。
   - Room 写入失败时恢复到权威顺序并显示明确错误，不得留下仅 UI 改序的状态。
4. **旅行日 rail 底部 `＋` 点击后直接追加一天。**
   - 不再弹出二次确认或配置弹窗；单击一次即调用现有追加旅行日流程，将新旅行日添加到末尾。
   - 提交期间按钮禁用并提供明确进行中反馈，防止连续点击重复追加。
   - 成功后 scope rail、日期范围、旅行日编号及列表卡片天数同步回流；是否自动选中新日按现有产品语义保持一致。
   - 失败时保留原旅行日和当前选中日，显示明确错误并允许重试。
   - 已定日期旅行追加后结束日期顺延一天；不得修改既有 day ID 或内容。
5. 按用户要求，本轮只记录，不修改代码；手动批次完成后统一修复和复验。

2. 核对“仅移除本次安排、收藏保留、相邻路线重算”。

## M7：地图、授权与定位权限

### 操作边界

- AMap 隐私同意和 Android 定位权限由用户亲自决定。
- Claude 不代为勾选同意、不代为授予或撤销系统权限。
- 真实 SDK failure 只在自然出现时记录。

### 操作步骤

#### M7-1 未授权 fallback

1. 在地图未授权状态进入工作台。
2. 检查 fallback 文案和“查看并授权”。
3. 切换地点池/行程，确认本地能力仍可用。
4. 打开图层菜单，检查三种图层和遮罩层级。

#### M7-2 AMap consent

1. 用户点击“查看并授权”。
2. 检查隐私政策入口、checkbox、“允许使用地图”和“暂不允许”。
3. 若用户选择允许，观察真实 AMap Loading → Ready。
4. 若用户选择暂不允许，确认回到 fallback 且本地内容保持。

#### M7-3 图层与手势

1. 在 RealAmap Ready 后切换标准、卫星、卫星路网。
2. 拖动/缩放地图。
3. 切换地点池、单日、全程再返回，确认普通状态变化不会覆盖用户手势。
4. 新增真实地点后只允许一次集合 refit。
5. cold start 检查图层偏好保留。

#### M7-4 定位权限

1. 点击定位。
2. 检查应用内定位说明。
3. 用户亲自继续到 AndroidSystem 权限请求并选择拒绝。
4. 再次尝试，若进入永久拒绝状态，检查系统设置引导。
5. 用户可自行进入系统设置授予；返回后确认只定位一次。

#### M7-5 地图失败

1. 仅当真实 SDK 自然失败时记录错误和重试。
2. 检查失败状态下本地 Tab、搜索、行程和唯一重试入口仍可达。
3. 不通过破坏 SDK、网络代理或数据伪造真实失败。

建议截图：fallback、授权说明、Loading、Ready 三图层、定位说明、系统权限、设置引导、自然失败（如发生）。

### M7 阻断标准

- 未授权导致本地功能不可用。
- AMap consent 与 AndroidSystem 权限混淆。
- 图层菜单或地图控件遮挡关键内容。
- 返回应用后重复定位。
- 地图失败后没有恢复入口。

## M8：异常、响应式与最终回归

### 操作步骤

#### M8-1 网络与恢复

1. 用户手动关闭网络。
2. 进入包含路线的行程，观察等待联网状态。
3. 恢复网络，观察路线自动恢复。
4. 若自然出现失败，点击唯一重试入口。

#### M8-2 保存失败

1. 仅在自然出现保存失败时手动验证。
2. 检查草稿完整保留。
3. “继续编辑”和“重新保存”均可达。
4. 无法自然触发时记录为自动化覆盖，不人为损坏数据库或请求。

#### M8-3 大字体与小窗口

1. 由用户在系统设置将字体调大。
2. 重新打开并依次检查：
   - 旅行列表主卡和创建入口
   - 创建表单及日期弹窗
   - 设置页和危险确认
   - 工作台更多/图层菜单
   - 地点详情查看与编辑
   - 加入行程目标选择和结果
   - 单日/全程行程
   - 行程项及路段编辑
3. 如设备支持分屏，再检查较窄窗口。
4. 用户完成后自行恢复字体设置。

#### M8-4 IME

1. 聚焦每类页面的最后一个输入字段。
2. 检查保存、取消和错误恢复操作仍可达。
3. 系统 Back 应先关闭键盘，再按业务状态关闭弹层。

#### M8-5 冷启动和返回栈

1. 确认测试数据已提交完成且没有进行中的保存。
2. 冷启动应用。
3. 检查已提交旅行、地点、行程和图层偏好保留。
4. 临时 Dialog、Sheet、错误提示和提交中状态不得恢复。
5. 完整执行：列表 → 工作台 → 设置 → 工作台 → 列表。
6. 确认无残留 overlay、无坏返回栈、无 crash/ANR。

建议截图：离线、恢复、大字体关键页、IME 最后一字段、cold start 列表和最终工作台。

### M8 阻断标准

- 网络恢复后状态卡死。
- 草稿在失败或键盘关闭时丢失。
- 大字体导致关键操作不可达。
- cold start 丢失已提交数据或恢复临时 UI。
- 返回栈进入已删除或无效页面。
