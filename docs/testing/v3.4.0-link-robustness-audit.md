# 小红书／携程链接导入健壮性审计

2026-10-14，46b4。**审计完成，未修复。** 用户询问是否还有换URL后可能失败的同类问题。本轮审查双平台链路、运行受控结构探针、复测携程原链接；不开发、不安装手机、不提交推送或发布。

## 总结

不能把“两个样本成功”当作“两个平台完整适配”。除了已复现的小红书新图片路径问题，现有代码还存在两类共性风险：

1. **误报失败**：正文／图片已齐，但张数格式、容器或链接类型不同，继续等待至超时或直接拒绝。
2. **误报完整**：只加载一张时猜测整帖单图，或混入推荐图／把视频封面当图文，可能未读全却通过。

这些需要按平台和内容类型系统加固，而不是继续按单条URL补条件。不能承诺平台改版、验证要求、删除／失效内容永远可读；应确保支持范围明确、正常变体有回归、失败原因准确且不静默漏图或混入其他帖。

## 本轮证据等级

### A. 真实页面／实际生产链路

- **携程原青州图文笔记**：隔离Android生产reader和图片loader，`articleId=353997561`完整原分享URL；**8.084秒测试通过，正文433字符、6张图、662,092字节**，均下载并解码。公开DOM是 `.swiper-item-image img`、`dimg04.c-ctrip.com/images/…`。未调用模型、高德或收藏。
- **另一种携程公开游记**：`https://gs.ctrip.com/html5/you/travels/898/4047530.html`，内置浏览器确实可见标题和正文；当前生产入口直接拒绝该URL。页面使用 `img.img_travels.con_img`，当前正文／轮播选择器命中均为0；37个文章图片元素中1个引用GIF。因此这是**未覆盖的内容类型**，不是已经承诺支持的图文笔记突然失败；不能仅放开域名就称支持，更不能绕过20图／静态图片边界。
- **小红书徐州**：前轮已用生产reader复现45.105秒超时，十张轮播图被旧路径过滤；本轮安全策略探针再次确认该路径格式被拒绝。小红书真实页面本轮未重跑，详细事实沿用[前轮诊断](v3.4.0-xhs-note-timeout-diagnosis.md)。

## 已有保护，不应为兼容性撤掉

- 失败不把分享标题冒充已读取正文送模型；整批下载／解码结束后才返回素材。
- 不支持来源、非HTTPS、身份信息URL、不安全公网地址和跨站导航限制。
- 20图／单图10MiB／累计30MiB、正文长度、静态图格式保护；数量范围不意味着任意20张大图都能成功。
- 失败回收本次新增素材，保留已有输入；不自动收藏。

当前测试已覆盖两种简化DOM、20图下载／计数、无效URL、取消回收等，但真实链接测试固定“青州＋6图”，不足以覆盖本次变化。不能用总JVM数量替代不同内容形态的适配测试。

## 建议下一轮修复与验收范围（未开始开发）

1. **两平台一起改，共用完整性约束。** 平台适配分开，分享输入、原帖绑定、安全下载和明确失败状态复用；不引入“任何网站通用抓图”兜底。
2. **优先防误成功。** 用原帖范围内可信媒体计数／清单和加载证据确认完整性；未知就明确未能确认完整，不依据一张图和短暂稳定猜测成功。
3. **多结构兼容而非单URL白名单。** 兼容已观察图片路径和轮播结构、谨慎处理懒加载／重复轮播／不同尺寸URL；保留源证据，排除头像、评论、推荐与广告。
4. **提前判定内容类型和失败原因。** 区分不支持的页面类型、需要验证、页面不可用、结构未兼容、缺图、超限和真实网络超时；原文保留，不静默降级成只读分享摘要。
5. **测试按形态而非数量刷通过。** 把本轮可复现结构固化为回归，覆盖不同作者／目的地／发布时间、单图／多图／10图／20图、两种小红书路径、正文折叠、张数变化、图片污染、视频／无正文／删除／超限。真实样本需要验证正文、原帖图像范围与下载解码，而不只是HTTP200。
6. **内容范围单独决定。** 携程长游记、视频、动图等目前不是同一适配；明确支持／不支持，不能借修bug绕开20图或扩大识别范围。
7. **补最小脱敏诊断。** 记录阶段、平台／适配版本、计数及失败类型，不记用户全文、签名URL、Token；将来换URL异常可直接定位。任何可见提示／交互改动仍走设计确认。

不承诺所有URL或平台未来改版100%成功；本轮也没有验证全部平台模板、全部设备WebView、真实20图帖、长时间网络、登录／验证码变化或所有图片CDN。
