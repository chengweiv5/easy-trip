## 现象与证据边界

手机旅行“徐州两日逛吃路线”的10张图片已导入，图2提示“图片返回格式不完整或不支持工具调用，未查询地点”。这一层位于模型响应解码，不是前一轮平台链接读取／图片下载问题。

手机那次模型原始响应没有保留，无法证明究竟是哪一个字段触发。本轮不把人工响应复现当作手机原始响应，不宣称手机图2问题已根治。此前16组人工响应探针已证明原生产解码器会因附加字段、普通地点父级空值、枚举大小写等差异拒绝整份素材。

## 实施规则

原则：**兼容格式差异，不编造事实，不静默遗漏。**

1. 文字地点、图片地点、最终语义整理仅提取约定字段，忽略附加字段。模型附加的坐标、query等不进入领域对象，不获得工具执行权限。
2. 普通 `PLACE` 的 `parentName` 缺失或null按空值处理；`DISTINCT_PART` 仍要求父级字段存在且非null，原有显式空字符串行为不变。作者标记／推荐依据等关键证据不补造。
3. 已知图片证据枚举和整理discard reason允许前后空白、大小写差异；未知枚举仍拒绝。
4. 单一、完整、预期工具调用允许 `finish_reason=tool_calls` 或 `stop`。截断、过滤、未知结束、多工具、未知工具仍拒绝。arguments仍须是JSON字符串，不从自由文本中搜索JSON。
5. HTTP成功但响应有可修复格式问题时，最多自动补救一次，单次解析最多两次模型调用。可补救项仅限缺少工具、arguments格式、必要字段及字段格式错误。重新发送同一原始资料和固定格式提醒，不回传失败模型输出。
6. 网络、HTTP错误、鉴权、限流、截断、地点与来源不符、作者证据不足、分组覆盖缺失／冲突不自动重发。协程取消仍立即生效。
7. 真正错误仍使该素材失败，不新增逐item部分接收。已完成素材缓存保留，手动重试只处理失败图片；全部素材完整后才整理／查询，不自动收藏。
8. 错误文案区分格式、必要字段、截断、工具和来源证据问题，不再统称“不支持工具调用”。复用现有错误展示区域，不新增页面。
9. `AppContainer` 共用最多64KiB的 `diagnostics/assistant-protocol.jsonl`。记录随机operation UUID、阶段、图序号、attempt、结果、原因枚举、failureCode与时间；不记录原文、URL、城市、图片ID／图片、模型原始响应或凭据。日志IO失败不使成功结果失败，也不触发重发。普通文字、链接正文、图片、语义整理均接入。

### 不扩大的范围

- 全局城市解析器和日期解析器本轮未改；不能宣称所有模型入口均已统一。
- 平台链接reader／图片下载器不在本轮修改范围。
- 100地点、20图、30天、城市优先创建、高德700ms／并发2、手动收藏不变。
- 版本仍3.4.0/build27/schema13，没有数据库迁移。
- 自动格式补救可能增加模型费用和耗时；既有总时限不变。20图最坏情况下可能有40次图片模型调用，此外仍有正文／整理调用，但不保证总时限内每份素材均能完成两次调用。
- 不保证未来任何模型响应／平台URL永远兼容；不将严格的事实／完整性校验替换为“能解析就算成功”。
