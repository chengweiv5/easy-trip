## 2. 实际实现

### 原帖读取与图片下载

- DOM adapter3 不再以图片数量齐全作为正文就绪条件。缺图、未知数量、超过20图不阻塞可读正文；仍拒绝错误原帖、限制页、视频及非法导航。
- `AssistantLinkLoader.read` 只返回正文及来源计划，不调用图片 fetcher。WebView 禁止网络图片，可信图片子资源也被拦截；保留 DOM 原图 URL 获取能力。
- 图片使用稳定 UUID、模型 slot、可证明时的原帖序号，保存 NOT_ATTEMPTED／AVAILABLE／SKIPPED 及真实原因；不是把失败解释为“无地点”。
- 下载总阶段30秒、最多2 worker；串行导入与字节预算控制，单图下载／解码／超限失败不撤销好图。只显式重试失败来源，缓存命中不重复下载。
- HTTPS、平台 CDN、原帖归属、公网地址、字节及像素安全约束保持。

### 城市、地点和收藏

- 全局城市先发独立文字请求，识别出城市即返回，不准备或发送图片。文字无城市才尝试有界图片辅助；日期继续可空。
- 生产地点入口统一由 `AssistantInputProcessor` **先文字、再图片**，图片辅助最多180秒。这是相对计划中并行设想的明确调整：正文不依赖图片准备，文字 AUTH 可直接阻止后续图片请求；不是承诺界面会在正文返回瞬间显示最终整理结果。
- 普通文字、图片、V1／V2提取共享全进程2路槽；图片仍按真实字节合组，不改回固定逐张地点提取。
- 成功来源继续整理／高德匹配／手动收藏。坏图的单源 OVERFLOW 不升级为全批超限；成功来源真实合计400候选、最终100地点门禁仍生效。
- 图片失败不禁用成功结果的收藏。一次收藏成功结束本批，失败／未选素材放弃；仅写入失败保留幂等重试。
- 用户取消、AUTH、记录摘要／结构／来源完整性错误不被伪装成可选图片失败。

### 恢复与 UI

- 材料存储 v2、结果封装 v3，模型协议 V1／V2独立标记；读取旧材料和旧结果，不改Room schema。
- 材料按 session＋digest 保存不可变快照，journal保存materialId；复制已绑定材料不覆盖源digest。派生图片缓存不改原材料引用。
- 非链接选图也交接完整plan；全部缺文件仍保留来源与SKIPPED，不变成无来由的空输入。
- 保留已验证图片证据，恢复复制保持已净化 JPEG 精确字节／摘要；AtomicFile防止失败重试删除旧文件。
- `bodyAvailable` 贯通保存草稿、retain、pinned fork，标题-only不冒充正文已取得。
- 新结果拒绝 V2 checkpoint与协议版本不一致、ID／slot／descriptor冲突及联合来源／字节超限。
- 现有UI展示“已跳过（可选）”，可选重试不挡收藏，无新页面、必选开关或首页重排。
