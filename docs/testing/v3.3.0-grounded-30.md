## 实现

### 作者目标与背景区分

旅行图片候选必须携带`targetBasis`、`targetDetail`、`entityRole`、`parentName`四项结构化证据，普通图片旧协议仍兼容。作者编号、图钉、标签和明确推荐与底图背景区分；正文中的附近参考也逐项阅读，不仅提取大标题。原名称逐字摘录，不凭默认城市补写名字。

最终整理仍由模型按本次资料进行：System是固定通用模板，旅行城市、正文和候选仅进入User。模型只能覆盖已有候选ID，不得创建名称、城市或坐标。明确作者目标若被整理阶段误删为BACKGROUND/NOT_PLACE，客户端保守恢复；食品和餐饮仍剔除。不是按是否含“村”“店”等字机械过滤。

新增唯一泛称检查：本次上下文唯一指向已有明确地点时，与之合并。父地点与独立子地点不因包含关系合并；客户端仅在有明确父名称证据或门向限定时拆分非法混组，同一子地点的短名/长名仍可合并。

独立门的地图匹配不再默认采用缺少门向限定的父POI：优先同城且门向一致的候选，没有则保留现有“待核对”交互，不造坐标。普通地点保持原有首条有效同城候选优先。

### 上限与UI

`AssistantPlacePolicy.MAX_PLACES=30`统一文字、普通图片、链接整理、控制器与收藏确认。图片MAX_IMAGES仍20，单项POI搜索候选20不是总地点限制；素材候选预算100/份、400/批不变。

标号A–Z之后为AA–AD。设备测试发现固定28dp徽标在大字体下换行裁切，已改为最小28dp、按文本宽高扩展、水平4dp内边距、单行；不缩小系统字号。选择热区仍至少48dp，没有新增页面或操作步骤。
