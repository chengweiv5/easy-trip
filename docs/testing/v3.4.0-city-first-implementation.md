## 实现

### 城市与素材

`assistant/cityfirst/` 新模块使用独立 `identify_trip_destination` 协议，不调用地点 parser／normalizer 或高德。固定 System Prompt 不含具体旅行实例。城市证据必须引用实际正文片段或实际发送的图片 ID；不把图片 ID 校验宣称为逐像素地理准确率验证。

正文足够时不再调用图片城市识别；不足时逐张读取已准备图片。仍复用生产链接读取、域名与完整性校验、受控图存储；不访问其他 App 登录态，不绕过验证页。单城作为默认城市，多城完整传递至文本／图片／整理的独立 user 上下文，归属不明的地点不套第一城或手机定位。

私有素材采用 UUID 句柄、摘要及图片校验。`withRetained` 将素材核验和数据库引用登记与清理串行；已提交素材不能被覆盖或提前释放。模型凭据不进入日志、Room 或仓库。

### 创建与恢复

schema12→13 只新增：

1. `assistant_trip_destinations`：旅行城市范围，删除旅行时级联。
2. `assistant_guide_handoffs`：交接、attempt、状态及结果引用，删除旅行时级联。
3. `assistant_guide_creation_receipts`：无旅行 FK 的独立创建回执，防止删除后重建旧旅行。

旅行、空白日、城市、PENDING 交接及回执同一个 Room 事务提交。原 schema12 表、旧创建命令／回执／日志保留；Room 生成 schema13 文件，未手填 identity hash。

新日志采用 AtomicFile、1MiB 上限、严格 UTF-8。未知／损坏记录保留并锁定，不被新会话覆盖。返回输入后未更换攻略时重新进入确认，保留人工城市、名称及日期，不再次请求模型；修改素材会清除旧未提交命令。

创建提交结果丢失时先恢复回执；同命令不重复创建，已删除旅行不会复活。`launchSingleTop` 限制重复全局入口。

### 一次交接与手动收藏

workspace 使用原 `onOpen`，不是只切 `open=true`；模型、地图授权、宿主就绪后才 CAS 领取 PENDING。已 CLAIMED 的未知请求不自动重发，用户主动重试并看到可能再次计费提示。

IMPORTED 保存完整候选／来源／POI／选择快照。恢复不再请求模型或高德；未完成查询变成可人工重试状态。收藏和 FINISHED 在同一数据库事务内完成，成功后沿用空白新轮并清理素材。失败、取消、零地点、101 地点保留旅行与原攻略。
