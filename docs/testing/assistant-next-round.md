## 用户确认的行为

“收藏按钮只点一次即可，点完立即清除本批候选，开始新一轮对话”。按已确认方案，清空发生在持久化成功之后，而不是点击瞬间丢弃草稿：

- 点击一次收藏所选地点，保存中锁定重复操作。
- 成功后结束整个批次：清空文字、图片、全部候选（包括未选与失败项）、选择、进度、详情/焦点与地图候选。
- 保留当前旅行、城市（含手动指定）、配置与已收藏地点；面板滚回空输入，显示“已收藏 N 个地点，可以继续输入。”，无确认页、清空确认或继续按钮。
- 失败保留输入、图片、候选与选择，重试复用原 operation ID。用户主动放弃草稿的手动清空确认仍保留。

## 实现边界

- Controller 在 Room 事务成功后取消旧查询、提升批次版本并重置草稿；迟到结果不能重新填充下一轮。数据库与导入事务未变。
- 成功回调同步清空 ViewModel 焦点、详情及图片恢复标记；只异步删除旧批次图片 ID，不释放复用中的整个图片会话，因此不阻塞新输入、不误删新一轮附件。
- 图片清理异常不会将已成功提交的收藏报告为失败。异常残留临时文件沿用会话释放/下次启动清理兜底；未模拟真实磁盘损坏。
- 仅成功回调结束批次，恢复历史回执不会触发业务清空。
- 保留统一城市来源、请求节流、透明底栏与全选间距修复；本轮未修改地点行间距。
